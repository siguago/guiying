# 安全审计跟进（2026-08-11）

本记录是 M0 复核后的独立跟进。审计范围包括完整哈希与逐字节比较、SQLite 操作约束、Tauri command 面、路径模型、依赖树和大规模扫描行为。

## 已封闭的高优先级缺口

1. 完整哈希现在要求实际读取长度与打开时声明长度完全一致；提前 EOF 与超出声明长度都会硬失败。
2. 逐字节比较按声明长度精确读取，随后额外探测 EOF；两边同时短读或同时多出数据都不能返回相同。
3. SQLite 禁止把 keeper 本身作为隔离/清理 source，并要求破坏性 source 的成员角色为 `candidate`。
4. 操作路径同时保存显示文本和原始编码字节；Unix 原始路径拒绝绝对路径、NUL、空组件、`.` 与 `..`。
5. 非 `mixed` batch 与 item 的动作类型必须一致；dry-run 不能进入执行态；隔离/恢复缺少目标路径时拒绝建项。
6. sidecar 时间修复门只接受 `confirmed` 关系，不再接受 `inferred` 关系。

上述修复仍不等于已经开放文件写入。当前 Tauri 只有只读扫描 command，运行时没有隔离、恢复、改时或永久删除 API。

## 供应链检查

- `pnpm audit --prod`：未发现已知漏洞。
- `cargo audit`：未发现直接 vulnerability；报告 17 条 warning。
- 其中 GTK3/ATK 警告来自 Linux 目标的 Tauri 传递依赖，不在当前 macOS 产物中执行。
- `glib 0.18.5` 有一条 RustSec unsound warning；它同样位于 GTK/Linux 目标依赖树。发布 CI 仍需按目标运行审计，并为所有临时例外记录上游、适用目标、负责人和到期日。
- `unic-*` 与 `proc-macro-error` 为 unmaintained 警告。不能把“无直接漏洞”表述成“依赖无风险”。

## 仍阻断写能力的事项

- SQLite 尚未接入运行时，卷身份、mount session 与单写者锁尚未实现；
- 无损原始路径必须由专用路径类型逐组件解析，禁止由展示文本寻址；
- 能力探测、file/parent-directory fsync、no-replace、卷端 manifest 与重启对账尚未完成；
- 时间解析器、逻辑资产和 keeper/time-donor 策略尚未实现；
- 短写、EIO、ENOSPC、掉盘、强杀和同名换盘的写侧故障注入尚未通过；
- 永久删除必须保持未编译、未注册状态，直到独立安全评审。

## 只读阶段仍需修复的规模问题

- 宽目录遍历已改成深度优先 frame，不再同时持有同层所有子目录 fd；嵌套深度默认限制为 64，超限会 `partial` 并保留文件。目录条目与总报告内存仍需通过持久化索引预算化；
- 报告需要增量落库与分页，不能把百万文件一次性经 IPC 发送给 React；
- 扫描需要 job id、互斥、取消、节流进度和重启恢复；
- 所有成功绑定并枚举的目录现在都会从根 fd 逐组件重开复核；任一深层目录变化都会中断整份定案并清空重复组；
- 原生掉盘、权限、部分报告和低 fd 限制需要故障测试。

在这些门槛完成前，产品发布上限仍是 Preview Read-only。
