# 归影安全设计与发布门槛

| 项目 | 内容 |
| --- | --- |
| 文档状态 | Normative，所有改变文件的实现必须遵守 |
| 版本 | 0.1 |
| 最近更新 | 2026-08-10 |

## 1. 安全目标

归影处理的是不可替代的个人数据。其安全设计不以“操作通常成功”为目标，而以故障时可证明的最坏结果为目标：

> 无论应用崩溃、系统睡眠、硬盘拔出、磁盘写满、驱动异常、文件并发变化或状态记录损坏，最坏结果只能是多保留副本或停止处理，不能丢失某组最后一份已验证的完整内容。

这一目标不等于数据备份。介质物理损坏、控制器故障、文件系统整体损坏和用户在其他工具中删除文件仍需独立备份防护。

## 2. 强制安全不变量

以下不变量属于 P0，任何功能、设置和用户确认都不能绕过：

1. **Last-good-copy**：每个被处理组在任意可观察状态至少有一份当前可完整读取、内容验证通过的副本。
2. **Content proof**：自动隔离只接受大小、完整 BLAKE3 和执行前逐字节比较全部一致的文件。
3. **Stable input**：比较前后文件身份、大小与时间快照一致；否则整组重新扫描。
4. **Donor preservation**：time donor 的信息未成功迁移并读回验证之前，donor 不得离开原路径。
5. **No overwrite**：隔离、恢复、复制和日志写入都不得覆盖已有不同内容。
6. **Durable intent**：没有可持久化、可恢复的冻结执行计划，不得开始任何文件变更。
7. **Volume binding**：执行计划必须绑定卷身份与挂载代次；同名卷或同路径不能替代身份验证。
8. **Fail closed**：未知能力、证据冲突、权限/I/O/空间错误、并发变化和恢复歧义都只能跳过或停止。
9. **Operation separation**：扫描、时间修复、隔离、恢复和永久清理是独立操作，不能在一个隐式步骤中串联。
10. **Complete audit**：每个计划、状态转换、写入和错误都有持久化记录，不能出现无来源的文件变更。

## 3. 威胁与故障模型

### 3.1 需要防护

- 扫描后文件被 Finder、同步工具、照片编辑器或另一个归影实例修改、替换、移动；
- 同名硬盘替换、重新挂载、驱动升级、挂载点复用；
- 应用在任意指令间崩溃或被强制退出；
- macOS 睡眠、用户注销、系统重启、异常拔盘；
- 写满、配额耗尽、短读、短写、延迟 I/O 错误、卷突然只读；
- 不可靠的 rename、时间写入、xattr/ACL/resource fork 和 fsync 语义；
- 畸形或恶意媒体触发解析器崩溃、过量内存或长时间计算；
- Unicode、大小写、超长路径和控制字符造成路径混淆；
- 日志或本地数据库部分写入、损坏、版本不兼容；
- 用户误解“相似”“隔离”“释放空间”或时间字段语义。

### 3.2 不在应用可独立保证范围内

- 硬盘物理损坏、控制器损坏、文件系统全局元数据损坏；
- 恶意 root 进程或内核/驱动故意欺骗读写结果；
- 用户或其他程序在归影之外删除所有副本；
- 没有独立备份时的永久删除后反悔。

对这些风险，产品必须清楚提示独立备份要求，不得把隔离区宣传为备份。

## 4. 运行模式与权限边界

| 模式 | 允许行为 | 进入条件 |
| --- | --- | --- |
| 只读扫描 | 枚举、读取、哈希、解析元数据、生成报告 | 默认模式；无需写探测 |
| 预演 | 创建冻结计划、重新验证，但不改变用户文件 | 本地状态存储可用 |
| 时间修复 | 修改 keeper 的受支持文件时间并读回 | 时间能力与证据均通过 |
| 同卷隔离 | 将确定重复项移动到同卷隔离区 | 所有执行前置条件通过 |
| 恢复 | 从隔离区恢复至原路径或安全冲突目录 | 事务与内容验证通过 |
| 永久清理 | 删除已隔离项 | MVP 禁用；未来独立启用且需额外门槛 |

应用应使用普通用户权限。不得要求 root，不得自动修改挂载参数，不得禁用系统安全功能。媒体解析器运行于单独的受限进程，禁止网络访问，设置每文件 CPU 时间、内存、输出尺寸和解压像素上限。

## 5. 信任边界与身份

### 5.1 卷身份

执行计划至少记录：

- 卷 UUID 或可用的持久化卷标识；
- 设备/分区标识、文件系统类型、驱动信息与挂载源；
- 挂载代次或应用观察到的 mount session ID；
- 大小写、只读、网络/本地属性与能力探测摘要；
- 计划生成时和执行时的挂载点，但挂载点仅用于寻址，不用于证明身份。

卷重新挂载、身份字段不可获得、关键能力改变或驱动版本改变时，旧能力档案和未执行计划全部失效，必须重新探测与预演。

### 5.2 文件身份

每个计划项至少记录：相对于卷根的原路径、文件类型、稳定文件 ID（若可靠）、设备 ID、大小、birthtime、mtime、ctime、完整 BLAKE3、快速指纹版本和逻辑资产关系。稳定文件 ID 不可用时，路径不得被视为身份，只能作为重新打开后的候选定位。

执行时必须以“安全打开 → `fstat` → 流式读取 → 再次 `fstat`”完成验证，禁止先校验路径再对同一路径执行破坏性操作而不重新确认打开对象。

## 6. 持久化记录

### 6.1 双份记录

任何写操作开始前必须存在两份可核对的记录：

1. **本机事务库**：SQLite，启用 WAL 或等价崩溃安全配置，存储完整计划、状态、错误和能力档案；
2. **卷上清单**：隔离区内追加式、带版本和校验和的事务清单，存储恢复所需的最小完整信息。

若卷不能可靠持久化清单，允许只读扫描但禁止修改文件。两份记录以事务 ID、计划摘要和递增序号关联。状态转换采用 append-only 事件，物化状态可重建；不能只原地覆盖一个 `state` 字段。

### 6.2 日志顺序

每次状态转换遵循：

1. 计算下一事件并写入本机日志；
2. 持久化并确认成功；
3. 写入卷上清单并按探测能力持久化；
4. 执行对应文件操作；
5. 重新读取文件状态与内容；
6. 追加结果事件到两份记录。

任一步失败即停止当前卷的后续写操作。恢复程序通过文件实际状态、两份事件序列和内容哈希收敛，不能仅相信数据库的最后状态。

## 7. 事务状态机

### 7.1 状态定义

```text
DISCOVERED
  └─> PLANNED
        └─> PREPARED
              ├─> BLOCKED
              └─> TIME_VERIFIED        （无需时间迁移时可记录 NOT_REQUIRED）
                    └─> MOVED_TO_QUARANTINE
                          └─> DESTINATION_VERIFIED
                                └─> COMMITTED

COMMITTED ──> RESTORE_PREPARED ──> RESTORED

COMMITTED ──> PURGE_ELIGIBLE ──> PURGED   （MVP 禁用）
任意未提交状态 ──> BLOCKED / NEEDS_RECONCILIATION
```

含义：

- `PLANNED`：用户已确认不可变计划，但尚未获得写权限；
- `PREPARED`：卷和文件已重新验证，隔离目标以随机事务 ID 预留且确认不冲突；
- `TIME_VERIFIED`：keeper 的时间写入成功并按卷精度读回，或明确无需写入；
- `MOVED_TO_QUARANTINE`：原路径操作已发生，但尚未证明目标完整；
- `DESTINATION_VERIFIED`：隔离项可读、身份与完整内容验证通过；
- `COMMITTED`：两份日志均记录该项目完成；
- `RESTORE_PREPARED`：恢复目标已检查，禁止覆盖；
- `RESTORED`：内容已回到原路径或安全冲突路径且验证通过；
- `NEEDS_RECONCILIATION`：记录与文件实际状态不一致，禁止继续自动处理。

每个转换必须可重复执行。重复执行不得覆盖文件、重复迁移时间或让状态倒退到不安全分支。

### 7.2 执行前置条件

进入 `PREPARED` 前必须全部满足：

- 卷身份、挂载代次和能力档案与计划一致；
- 本机事务库与卷上清单可写、可读回且剩余空间满足保守预算；
- keeper 与候选副本均为当前可读的普通文件；
- 文件状态与计划一致，完整 BLAKE3 一致，随后逐字节复核一致；
- 复核前后 `fstat` 快照一致；
- keeper 不位于隔离区，隔离目标未存在；
- 逻辑资产关系明确，独有元数据已有安全归并计划或整组跳过；
- 并发锁/协调成功，应用未检测到另一写入实例；
- time donor 已确定且其迁移策略可执行；
- 没有当前卷级 I/O、权限、只读、空间或日志错误。

## 8. 安全文件操作

### 8.1 首选：同卷原子移动

能力探测证明同卷 no-replace rename 可靠时：

1. 在隔离区按事务 ID 创建不可预测目标目录；
2. 记录并持久化 `PREPARED`；
3. 使用“不覆盖”语义将候选移动到隔离路径；
4. 重新打开目标，校验文件身份、大小、完整 BLAKE3，必要时与 keeper 逐字节比较；
5. 记录 `DESTINATION_VERIFIED` 后提交。

不能通过“先判断目标不存在，再普通覆盖式 rename”模拟 no-replace；该做法存在 TOCTOU 风险。

### 8.2 rename 不可信时的 fallback

若同卷 rename 或目录持久化语义未达到隔离等级：

1. 只允许复制到隔离区随机 `.partial` 文件；
2. 写入、关闭、重新打开并计算完整 BLAKE3；
3. 将 `.partial` 以不覆盖语义提升为 `.ready`（若该能力也不可信，则保持 `.partial` 并仅报告）；
4. **保留原文件，不自动移除源路径**。

因此该 fallback 是“额外安全副本/演练”，不是完成去重。跨卷目标同样只允许复制并验证，永不自动删除源文件。

### 8.3 元数据与伴随内容

- data fork 相同但 xattr、Finder 标签、ACL、resource fork 不同的文件不能直接视为可无损舍弃；必须归并成功并验证，或人工选择后仍保留报告；
- AppleDouble `._*` 与对应文件作为逻辑资产处理，不可在不了解目标卷原生元数据支持时单独删除；
- Live Photo 图片与配对视频、AAE/XMP/JSON 等伴随项关系有歧义时整组阻断；
- 符号链接、Finder alias、硬链接、克隆、稀疏文件、包、设备和 socket 不进入普通自动隔离路径。

## 9. 时间写入安全协议

时间修复先于 donor 隔离，并单独形成子事务：

1. 保存 keeper 原 birthtime/mtime、donor 证据、时区语义、精度和规则版本；
2. 验证目标卷支持所需字段写入以及预期舍入；
3. 仅写用户确认且证据满足阈值的字段；
4. 关闭并重新打开 keeper，读回 birthtime/mtime；
5. 将读回值归一到该卷声明的精度后比较；
6. 校验 keeper 内容 BLAKE3 未改变；
7. 两份日志记录成功后进入 `TIME_VERIFIED`。

失败时按以下顺序 fallback：

- birthtime 不可写但 mtime 可写：仅在计划明确允许时修复 mtime，并在 UI/报告标明；
- 值发生已知、可接受的文件系统舍入：记录原值与实际值，按能力档案验证；
- 写后值未知、内容变化、错误或证据冲突：尝试恢复旧时间并读回，整组阻断，donor 保留；
- 无法恢复旧时间：标为高优先级异常，停止该卷所有后续写操作。

不得以当前 Mac 时区武断补全无时区拍摄时间；不得用 mtime 冒充 creation/birth time；不得因同一错误副本数量多而提高置信度。

## 10. 恢复与对账

启动、重新挂载和发现未完成事务时必须先对账，写操作在对账完成前禁用。

| 原路径 | 隔离路径 | 内容状态 | 恢复动作 |
| --- | --- | --- | --- |
| 存在 | 不存在 | 原文件与计划一致 | 视为尚未移动，可重新预演 |
| 不存在 | 存在 | 隔离文件验证通过 | 收敛为已移动，补记状态 |
| 存在 | 存在 | 两者相同 | 两份都保留，标记待确认 |
| 存在 | 存在 | 两者不同 | 停止该组，不覆盖，人工对账 |
| 不存在 | 不存在 | 无可验证副本 | 严重 P0 事件，停止整个批次 |
| 任意 | 任意 | 日志身份或哈希冲突 | `NEEDS_RECONCILIATION`，禁止自动处理 |

恢复到原路径前使用 no-replace 创建。若原路径已有：

- 内容完全相同：保留两份或在用户确认后保持现状，不覆盖；
- 内容不同：恢复到卷上 `Recovered/<事务 ID>/`，保持原相对路径并处理命名冲突；
- 目标目录不存在：逐级创建专属目录且验证不穿越符号链接。

恢复在任意状态点崩溃后必须可再次执行，并得到相同的安全结果。

## 11. 自动处理禁止条件

出现任一条件，当前组不得自动修复时间或隔离；卷级异常出现时应停止整个卷：

- 没有一份当前可完整读取并验证的 keeper；
- 仅依据文件名、时间、大小、快速/像素/感知哈希；
- 完整哈希或逐字节比较不一致；
- 文件在扫描、复核或执行中发生变化；
- 卷身份、挂载代次、驱动或事务记录不确定；
- 不能可靠写入并读回两份事务记录；
- 出现 I/O、短读/短写、权限、配额、空间、卷只读或 fsync 错误；
- time donor 尚未安全迁移，或写后验证失败；
- Live Photo/sidecar/AppleDouble 关系有歧义；
- 存在无法保存或归并的独有 xattr、ACL、Finder 标签、resource fork；
- 对象为符号链接、特殊文件、未知包、云端占位符、正在下载/写入的文件；
- 隔离目标冲突或只能使用覆盖语义；
- 解析器超时、崩溃、内存超限或返回自相矛盾的元数据；
- 用户未对永久清理进行独立确认，或没有已验证的外部备份声明。

禁止条件不能通过“高级模式”“我知道风险”等通用开关绕过。未来如需支持，必须针对具体能力提出新的可验证协议。

## 12. 边界情况清单

实现和测试必须覆盖：

### 12.1 文件与资产

- HEIC/JPEG/PNG/GIF/TIFF、常见 RAW、MOV/MP4、超大文件、空文件、截断文件；
- Live Photo、AAE、XMP、Google Takeout JSON、THM、AppleDouble；
- RAW+JPEG/HEIC、ProRAW、HDR、Portrait、连拍、编辑版和导出压缩版；
- 相同 data fork 但不同扩展元数据；
- 符号链接、Finder alias、硬链接、APFS clone、稀疏文件、包和特殊文件；
- 云端占位文件、资源尚未完全下载、读取中继续增长的媒体。

### 12.2 路径与目录

- NFC/NFD、emoji、换行、控制字符、前后空格、尾随点、保留名；
- 仅大小写不同的文件名、超长组件/路径、无权限目录、循环链接；
- 重叠扫描根、隔离区位于扫描根内、目录内嵌其他挂载卷；
- 同名硬盘、挂载点改变、卷重新挂载、目录被并发移动。

### 12.3 时间

- 1970、1980、1904、未来日期、非法闰日、亚秒丢失；
- DST 重叠/跳跃、无时区、正负 UTC 偏移、整数小时冲突；
- FAT 本地时间与 NTFS/APFS UTC 语义差异、文件系统时间舍入；
- 大批文件共享同一秒/分钟的复制时间；
- EXIF、QuickTime、sidecar 和文件系统时间强证据冲突。

### 12.4 故障与并发

- 两个归影实例、Finder、备份/同步工具、杀毒软件同时访问；
- 应用崩溃、系统休眠/重启、网络中断、拔盘再插；
- 磁盘写满、配额变化、坏块、短读/短写、权限中途改变；
- 本机事务库损坏、卷上清单损坏、两份日志进度不一致；
- 同名不同卷占据旧挂载路径，或原卷以只读方式重新挂载。

## 13. 故障注入与 P0 发布门槛

### 13.1 必测注入

| 类别 | 注入点 | 必须结果 |
| --- | --- | --- |
| 进程故障 | 每个事务状态转换前后强杀 | 重启可对账；不变量不破坏 |
| 介质故障 | 哈希、写时间、移动、验证、日志刷盘时拔盘 | 立即停止写入；重新挂载后身份验证与对账 |
| 容量故障 | 日志写入、隔离目录创建、复制时磁盘满/配额满 | 不清空隔离腾空间；保留原文件；卷级停止 |
| I/O 故障 | 短读、短写、延迟 EIO、fsync 失败 | 不提交；目标不被信任；保留源文件 |
| 并发故障 | 扫描后替换路径、比较中修改、并发移动 | 文件状态变化被检测，整组失效 |
| 身份欺骗 | 同名卷、同挂载点、重建目录和复用文件名 | 计划拒绝执行 |
| 状态损坏 | 损坏 SQLite、截断卷上清单、制造日志分歧 | 进入对账/只读，不猜测提交 |
| 元数据故障 | birthtime 不支持、舍入、写后不同、xattr 丢失 | 正确降级；donor/独有元数据保留 |
| 路径攻击 | symlink 替换、大小写/Unicode 冲突、超长路径 | 不越界、不覆盖，组阻断 |
| 解析器故障 | 畸形媒体、解压炸弹、超时、崩溃 | 解析器终止；D1 扫描与主进程稳定 |
| 恢复故障 | 恢复中每步强杀、目标已有相同/不同内容 | 幂等；不同内容不覆盖 |

### 13.2 文件系统测试集合

至少覆盖 APFS（普通、加密、大小写敏感）、HFS+、exFAT、FAT32、macOS 原生只读 NTFS、一个明确记录版本的第三方 NTFS 驱动、SMB 和模拟不可靠 FUSE。每类都要测试重新挂载与时间精度，不允许以文件系统名称代替能力探测。

### 13.3 P0 退出条件

允许发布“可隔离版”必须全部满足：

1. 对基准语料 D1 自动隔离零误判；
2. 所有状态点故障注入均未违反 Last-good-copy；
3. 同名换盘、TOCTOU、symlink 和并发修改场景均拒绝执行；
4. 两份日志任一损坏时不会自动猜测或继续写入；
5. donor 写回失败时 donor 从未被隔离；
6. 恢复在所有注入点均幂等，且从不覆盖不同内容；
7. 任一写操作都有完整审计事件，且可由日志重建；
8. 禁止条件有自动化测试，并且前后端都不能绕过核心层判断；
9. 模糊资产关系、独有扩展元数据和特殊文件均默认保留；
10. P0 测试需在 CI 模拟环境与真实外置介质演练中同时通过。

任一条件未满足时，只能发布只读扫描和报告能力。

## 14. 永久清理的额外要求

MVP 不实现自动永久清理。未来启用前必须另行评审并满足：

- 清理与去重执行分离，使用独立确认和独立事务；
- 每个隔离项重新验证 keeper 仍存在、可读且内容匹配；
- 清理范围由逐项清单确定，不对宽泛路径做递归删除；
- 用户明确确认已拥有另一介质或云端的独立备份；
- 处理隔离保留期、恢复演练、磁盘空间预估和清理中断恢复；
- 删除后报告准确说明不可由归影恢复。

## 15. 安全评审要求

任何影响以下内容的变更必须进行安全评审：重复判定、文件身份、卷身份、时间解析/写入、事务状态机、持久化顺序、隔离/恢复路径、禁止条件、解析器权限和永久清理。评审需要包含新故障注入用例，不能只审核正常路径。
