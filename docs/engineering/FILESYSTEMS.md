# 文件系统能力探测与降级策略

| 项目 | 内容 |
| --- | --- |
| 文档状态 | Normative，执行引擎不得仅按文件系统名称决定行为 |
| 版本 | 0.1 |
| 最近更新 | 2026-08-10 |

## 1. 设计原则

文件系统名称只能作为风险提示，不能作为能力证明。相同 NTFS 在 macOS 原生驱动和不同第三方驱动下表现不同；相同 SMB 名称背后也可能是不同服务器实现。归影必须基于当前挂载会话的实际能力探测决定可以执行的操作。

核心规则：

1. 扫描阶段只读，不为了探测而创建文件。
2. 用户进入预演/执行时，才在归影专属探测目录内做最小写入测试。
3. 每份能力档案绑定卷身份、挂载代次、驱动和应用探测协议版本。
4. 重新挂载、驱动变化、关键能力变化后旧档案立即失效。
5. 能力未知、测试失败或结果自相矛盾时降级，不从“常见行为”推测。
6. 执行中的实测结果优先于档案；任何异常立即使当前卷停止写入。

## 2. 能力等级

| 等级 | 名称 | 允许行为 |
| --- | --- | --- |
| C0 | 不可访问 | 不扫描；仅解释权限/挂载问题 |
| C1 | 只读扫描 | 枚举、读取、哈希、报告；不创建卷上日志 |
| C2 | 可验证复制 | 可向专属目录复制 `.partial` 并读回验证；源文件永不自动移除 |
| C3 | 安全同卷隔离 | 支持可靠 no-replace 同卷移动、持久化清单与恢复 |
| C4 | 时间修复 | 在 C3 基础上，目标时间字段可写且精度/语义已验证 |
| C5 | 永久清理候选 | 在 C3/C4 基础上通过额外删除与恢复门槛；MVP 不启用 |

能力按最小项决定，且可以拆分显示。例如某卷可能为“隔离 C3，birthtime C1，mtime C4”。UI 不得用一个“完全兼容”标签掩盖字段差异。

## 3. 卷能力档案

### 3.1 身份与环境

每次探测记录：

- 卷 UUID/持久标识、BSD 设备或挂载源、分区标识；
- 文件系统名称与版本（可用时）、驱动提供者与版本；
- 本地/网络、可移除、内部/外部、加密、只读、挂载选项；
- 挂载点、容量、可用空间、配额信息与探测时间；
- 当前应用版本、探测协议版本、mount session ID。

卷名称和挂载路径不是身份。没有足够身份信息时最多 C1。

### 3.2 路径与命名能力

- 大小写敏感与保持大小写；
- Unicode 正规化和名称往返一致性；
- 单组件和全路径长度；
- 前后空格、尾随点、换行、控制字符与保留名行为；
- 仅大小写或仅正规化形式不同的名称是否冲突；
- 符号链接、硬链接、Finder alias 的识别能力；
- 稳定文件 ID/inode 在 rename、关闭重开和重新挂载后的表现。

探测文件使用随机生成的安全 ASCII 名称，不主动创建危险控制字符；复杂名称能力优先通过只读观察和离线测试卷验证。生产卷中发现无法安全往返的路径时，该项目只读处理。

### 3.3 文件操作能力

- 创建新文件/目录时的不覆盖语义；
- 同目录与跨目录、同卷 rename 是否原子；
- no-replace rename 是否真正拒绝已存在目标；
- 文件数据持久化、目录项持久化和错误传播能力；
- 短写检测、关闭后读回、重开后读回；
- 空间预分配、稀疏文件、clone/reflink 和硬链接语义；
- 删除语义仅记录，不作为 MVP 写入前置能力。

“系统调用返回成功”不等于持久化完成。不能证明掉盘后的目录项持久性时，等级不得超过 C2。

### 3.4 时间能力

对 birthtime/creation time、mtime 分别探测：

- 字段是否可读、可写；
- 1970 之前和未来时间范围；
- 亚秒精度、实际舍入方向和最小分辨率；
- 写入后立即读、关闭重开读、短暂卸载重挂后的往返结果；
- 存储语义是 UTC、本地墙上时间还是服务器解释；
- DST 重叠/跳跃和显式 UTC 偏移的表现。

atime/ctime 不作为用户拍摄时间，但其变化需在审计中理解。Finder“添加日期”与 Spotlight 属性不视为可移植文件系统能力。

### 3.5 扩展元数据

分别探测或观察：

- xattr 名称/值往返与大小限制；
- Finder 标签、quarantine 等常见扩展属性；
- POSIX mode、所有者、ACL；
- resource fork；
- AppleDouble 是否由驱动生成及与原生元数据的转换关系。

归影不应复制系统安全属性来绕过平台限制。无法无损归并的独有扩展元数据会阻断自动隔离，而不是被静默丢弃。

## 4. 探测流程

### 4.1 只读探测

挂载后先通过系统 API 收集卷信息，并对用户选中的真实文件做非破坏性观察：读取属性、检查文件 ID 稳定性、识别挂载边界和特殊对象。只读探测不得修改 atime 的策略应尽可能使用平台支持的 no-atime/缓存方式；无法避免时必须披露。

### 4.2 写探测

仅在用户请求预演/执行后进行：

1. 在选定卷根或隔离区父目录创建 `.guiying/probes/<随机事务 ID>/`；
2. 写入带随机内容和校验和的小文件，关闭、重开并验证；
3. 测试 no-replace create、同卷 rename、目标冲突、文件与目录持久化；
4. 在独立探测文件上写入多组 birthtime/mtime，读回推导精度与语义；
5. 测试小型 xattr/ACL/resource fork（仅当系统允许且不会提权）；
6. 记录结果并尝试清理探测目录；
7. 清理失败不递归强删，保留路径到报告并将该卷写能力降级。

探测必须具备总超时、单操作超时和空间上限。探测目录不得跟随符号链接；每级目录都需验证仍位于目标卷。

### 4.3 档案失效条件

- 卷卸载或重新挂载；
- UUID/设备/分区/服务器分享标识变化；
- 驱动、挂载选项、只读状态变化；
- 应用探测协议升级；
- 执行中出现与档案不符的时间、rename、fsync、xattr 或文件 ID 行为；
- 系统从睡眠恢复后无法确认原 mount session；
- 网络分享断连重连。

失效后立即停止写入；已有事务先依据 [SAFETY.md](./SAFETY.md) 对账。

## 5. 文件系统默认矩阵

下表是未探测前的风险默认值，不是能力许可。实际行为取“表中上限”和“探测结果”的较低者。

| 文件系统/挂载方式 | 未探测默认 | 探测后最高建议 | 主要风险 | fail-closed fallback |
| --- | --- | --- | --- | --- |
| APFS（普通/加密） | C1 | C4 | clone 导致逻辑大小不等于实际释放；卷锁定；快照保留空间 | 只报逻辑重复与不确定的物理节省；解锁且探测通过才写 |
| APFS 大小写敏感 | C1 | C4 | UI/路径层误把大小写不同名称合并 | 使用字节级路径标识；冲突项目跳过 |
| HFS+ | C1 | C4 | Unicode 正规化、大小写配置、时间精度差异 | 路径往返或时间验证失败则项目/字段降级 |
| exFAT | C1 | C3；mtime 可单独到 C4 | 异常拔盘容错弱，Apple 元数据常用 `._`，时间/UTC 偏移与驱动实现差异 | 更保守的卷级停止；birthtime 未验证则只报告；保留 AppleDouble |
| FAT32 | C1 | C2/C3；时间通常不超过字段级 C2 | 4 GiB 文件限制、时间精度粗、本地时间语义、无原生 xattr/ACL | 不自动修复时间；有独有元数据或大文件则跳过 |
| NTFS（macOS 原生） | C1 | C1 | 通常只读 | 只读报告 |
| NTFS（第三方驱动） | C1 | C3/C4，必须按具体驱动验证 | 驱动质量、缓存、时间与扩展属性映射不一致 | 任何未知行为降为 C1；rename 不可信时最多 C2 |
| SMB | C1 | 默认上限 C2；经受控认证可评审 C3 | 断网、服务器缓存、锁、文件 ID、rename/fsync 语义依实现变化 | 复制并验证但保留源；断连后重新识别分享与会话 |
| NFS | C1 | 默认上限 C2 | close-to-open 缓存、锁与身份语义、服务器配置 | 只读或复制保源 |
| FUSE/云盘挂载 | C1 | 默认上限 C2 | 占位符、延迟上传、伪造 inode、非本地持久化 | 只读；能证明完整落地时也仅复制保源 |
| MTP/PTP 手机连接 | C0/C1 | C1 | 不是普通 POSIX 随机访问文件系统 | 仅导入到受支持本地卷后扫描 |
| 光盘、只读镜像、只读卷 | C1 | C1 | 无写能力 | 报告与导出计划 |
| 未知文件系统 | C1 | 默认上限 C2，需专项评审提高 | 语义未知 | 只读报告；不得猜测 |

网络文件系统和第三方驱动若要提高默认上限，必须增加受支持实现的版本矩阵、真实断连/掉电测试和专项安全评审。

## 7. 时间语义处理

### 7.1 统一内部表示

每个时间值保存：

- 原始字段和值；
- 解析后的本地日期时间；
- UTC instant（仅在偏移已知时）；
- UTC offset/时区是否显式；
- 精度（天、秒、10 ms、纳秒等）；
- 来源、解析器版本、置信度和异常标记。

无时区值不能被自动转换为 UTC instant。文件系统仅支持较低精度时，应保存高精度原证据到审计记录，并明确展示实际写回值。

### 7.2 典型差异

- APFS/NTFS 常以 UTC 基准表达时间，但 API/驱动仍需实测；
- FAT 系列通常具有本地时间语义和较粗分辨率，跨 DST/时区往返可能改变观察值；
- exFAT 包含本地时间及 UTC 偏移相关字段，但驱动可能不完整暴露；
- SMB/NFS 时间由客户端与服务器共同解释，时钟偏差和缓存需考虑。

归影不得仅凭上述典型行为写入时间。每个字段均以写探测和写后读回为准。

### 7.3 时间 fallback

| 问题 | 行为 |
| --- | --- |
| birthtime 不可写 | 不修复 birthtime；可独立建议 mtime 或仅报告 |
| mtime 可写但舍入 | 在已探测精度内写入并记录实际值 |
| 无时区证据 | 保留墙上时间语义，不套当前 Mac 时区 |
| 重新挂载后值变化 | 能力档案失败，停止该卷写入并对账 |
| 只支持 AppleDouble 映射 | 不假定等价于原生属性；保留 sidecar 并人工复核 |
| 多个强证据冲突 | 不自动写时间，donor 均保留 |

## 8. 路径、链接与挂载边界

- 所有内部路径保存为卷根相对路径和可逆字节表示；展示字符串不能用于重新寻址；
- 扫描根末组件为符号链接时拒绝进入；根目录绑定后，树内组件以目录句柄逐级打开且不跟随符号链接。根路径中稳定的祖先系统别名可能由操作系统在首次绑定时解析，因此不能把展示路径当作信任证明；
- 每次打开后验证对象类型与设备 ID，并用已打开目录的 `(device, inode)` 防循环；身份重复在未知驱动上必须使报告降级为 partial；
- 扫描根重叠时以文件身份/规范范围去重，但不能用会改变 Unicode 字节的字符串规范化定位文件；
- 遇到子目录 `st_dev`/卷标识变化即视为挂载边界，除非它是用户显式添加的独立根；
- 隔离区与恢复区不得位于符号链接之下；
- 目标名称由事务 ID 生成，不直接拼接不可信原始文件名；原始层级以清单保存；
- 恢复原文件名产生大小写或正规化冲突时，恢复至 `Recovered/<事务 ID>/` 并保留原名元数据。

## 9. 空间与物理存储

报告必须区分：

- **逻辑重复大小**：候选文件逻辑长度之和；
- **预计可回收空间**：考虑硬链接、clone/reflink、压缩、稀疏文件、快照后的估计；
- **已确认回收空间**：只能在未来永久清理后重新查询卷得出。

隔离的同卷 rename 通常不释放空间。复制 fallback 反而需要额外空间。执行前空间预算包括日志、探测、复制 fallback、安全余量和文件系统保留空间；不足时禁止写入，不得通过自动清空隔离区解决。

## 10. 运行时 fallback 表

| 运行时事件 | 范围 | 强制行为 |
| --- | --- | --- |
| 卷只读或权限不足 | 卷 | 停止写入，保留只读报告 |
| 卷身份/挂载代次不一致 | 卷 | 计划失效，重新识别与探测 |
| 本机或卷上日志不可持久化 | 卷 | 禁止所有变更 |
| no-replace/rename 探测失败 | 动作 | 降为 C2 复制保源或 C1 |
| birthtime/mtime 写后不一致 | 字段/卷 | 恢复旧值；donor 保留；异常行为则卷级停止 |
| xattr/ACL/resource fork 不可保留 | 组 | 整组人工复核，不自动隔离 |
| 文件 ID 不稳定 | 文件 | 依赖打开后内容与状态复核；不能满足则跳过 |
| 空间、配额或 I/O 错误 | 卷 | 立即停止，不清理其他数据腾空间 |
| 网络断开或 FUSE 后端离线 | 卷 | 中止；重连视为新 mount session |
| 文件扫描后变化 | 组 | 计划项失效并重新扫描 |
| 探测目录清理失败 | 卷 | 记录孤儿路径，降低写能力，不递归强删 |
| 未知错误 | 卷 | fail closed 到 C1，等待人工诊断 |

## 11. 验收测试矩阵

每个声称支持写入的文件系统/驱动组合至少验证：

1. 新格式化卷与已有大量文件的卷；
2. 大小写/Unicode 冲突、长路径和 AppleDouble；
3. 1 B、空文件、跨缓冲区文件、超大文件；
4. birthtime/mtime 多个边界值、DST、亚秒和重新挂载；
5. no-replace 冲突、跨目录 rename、目录持久化；
6. 硬链接、clone、稀疏文件及空间估计；
7. 每个事务状态点崩溃、拔盘、写满、短读/短写；
8. 换同名卷、换挂载点、驱动/挂载选项变化；
9. 卷上清单截断、本机数据库损坏和双日志分歧；
10. 隔离和恢复的幂等性。

测试结论按“文件系统 + 驱动版本 + macOS 版本 + 传输方式”记录。未覆盖的组合在产品中显示为“未经验证”，默认 C1。
