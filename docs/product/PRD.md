| 项目 | 内容 |
| --- | --- |
| 文档状态 | Draft，作为 MVP 实现与验收基线 |

| 最近更新 | 2026-08-10 |
| 目标平台 | macOS 桌面端，本地运行 |

## 1. 产品定义

归影是一款面向个人照片归档的本地桌面工具。它在移动硬盘或用户选择的目录中识别重复照片与视频，帮助用户保留合适的副本，并从重复副本中抢救可信的拍摄时间。所有改变文件的操作必须可预览、可审计、可恢复；遇到无法证明安全的情况时，产品必须保留文件并降级为只读报告。

一句话承诺：**快速找出真正重复的照片，在不丢失最后一份有效内容和可信时间信息的前提下完成整理。**

## 2. 背景与用户问题

用户长期将手机中的照片全量复制到移动硬盘，形成以下问题：

- 同一文件被重复复制到多个日期目录，文件名也可能被系统追加序号；
- 部分复制方式重置了文件创建时间或修改时间，使 Finder 时间不再等于拍摄时间；
- 某个重复副本的路径更适合保留，但另一个副本才持有正确时间；
- Live Photo、AAE、XMP、JSON 等伴随文件使“删一张照片”不再是单文件问题；
- 移动硬盘可能是 APFS、HFS+、exFAT、FAT32、NTFS 或网络文件系统，写入和时间语义不同；
- 用户无法接受因误判、掉盘、写满、崩溃或恢复失败而丢失照片。

## 3. 目标与非目标

### 3.1 MVP 目标

1. 快速、增量地扫描用户选择的目录，准确识别字节级完全重复文件。
2. 把“保留哪个文件”和“采用哪个文件的时间”作为两个独立决策。
3. 对时间证据给出来源、置信度与冲突解释，高置信度时才允许修复。
4. 在文件系统能力允许时，把待清理副本移动到同卷隔离区；支持崩溃恢复与幂等还原。
5. 在任何不确定或异常状态下 fail closed：不改变源文件，只生成报告。
6. 为每次扫描和执行生成可导出的审计报告。

### 3.2 MVP 非目标

- 不直接修改 Apple Photos 的 `.photoslibrary` 包内容，也不替代 Photos 数据库修复工具；
- 不使用文件名、日期、快速指纹或感知哈希作为自动移除依据；
- 不自动删除“看起来相似”的连拍、裁剪、压缩、滤镜或格式转换版本；
- 不默认写入 EXIF、QuickTime 容器或其他媒体内部元数据；
- 不提供云同步、相册管理、图像编辑或人脸识别；
- 不承诺从已损坏介质中恢复数据；隔离区不是备份；
- MVP 不自动永久删除隔离区内容。

## 4. 用户与核心任务

### 4.1 主要用户

长期将手机照片手工复制到外置硬盘，照片量从数万到数十万，重视隐私与原始文件完整性的个人用户。

### 4.2 核心任务

1. 选择一个或多个扫描根目录，并确认排除目录。
2. 只读扫描，查看节省空间预估、确定重复组、时间异常和未处理项目。
3. 为每组确认保留项（keeper）及时间来源（time donor）。
4. 预演执行计划，确认哪些文件会移动、哪些时间会改变、哪些项目因风险跳过。
5. 执行到隔离区；在之后的任意时间恢复。
6. 导出报告，并在有独立备份后单独处理永久清理。

## 5. 核心术语与不变量

- **内容文件**：照片、视频或其他受支持的普通文件。
- **逻辑资产**：一个内容文件及与其绑定的 Live Photo 配对文件、AAE、XMP、JSON、THM 或 AppleDouble 等伴随项。
- **重复组**：经某一重复等级判定属于同组的一个或多个内容文件。
- **keeper**：本次计划最终保留在用户照片目录中的副本。
- **time donor**：为 keeper 提供可信拍摄时间或文件时间证据的副本；它可以与 keeper 不同。
- **隔离区**：位于原卷上的归影专属、不可被普通扫描再次纳入的目录。
- **执行计划**：执行前冻结的、带文件身份与哈希的不可变操作集合。

任何实现都必须满足以下不变量：

1. 每个被改变的重复组，在任意故障点至少仍有一份已验证的完整内容。
2. 未经完整内容校验，不得把文件列为可自动隔离的“确定重复”。
3. time donor 的可信信息成功迁移并读回验证之前，不得隔离该 donor。
4. 未知能力、冲突、I/O 错误和并发变化一律增加保留量，不能增加删除量。
5. 扫描、隔离、恢复与永久清理是相互独立的用户动作。

## 6. 重复判定模型

### 6.1 三层定义

| 等级 | 定义 | 判定方式 | MVP 行为 |
| --- | --- | --- | --- |
| D1 字节完全相同 | 文件所有字节相同，文件系统时间可不同 | 文件大小分桶 → 分段快速指纹过滤 → 完整 BLAKE3 → 执行前逐字节复核 | 可进入自动隔离候选 |
| D2 解码画面相同 | 校正方向并解码后的像素相同，但封装、编码或元数据不同 | 受限解析器中解码，比较尺寸、色彩/方向归一化后的像素摘要并最终逐像素验证 | MVP 仅标记和人工复核，不自动处理 |
| D3 视觉相似 | 连拍、裁剪、压缩、滤镜、不同格式导出等视觉上相似 | 感知哈希或向量检索，只作为候选召回 | MVP 后置；永不默认自动处理 |

快速指纹、文件名、目录名、时间、尺寸、预览缩略图都不是 D1 的最终证据。D1 在执行前必须重新打开文件并做逐字节比较；文件在比较前后发生变化时整组失效并重新扫描。

### 6.2 扫描性能策略

1. 仅枚举普通文件；符号链接、云端占位符和特殊文件默认跳过。
2. 先按文件大小分桶，单例大小无需读取内容。
3. 对候选读取首部、中部和尾部生成快速指纹。
4. 对快速指纹相同者流式计算完整 BLAKE3。
5. 索引保存在 Mac 本地 SQLite 中，按卷身份、稳定文件 ID（可用时）、路径、大小和时间快照管理。
6. 仅当卷身份和文件状态未变化时复用哈希；执行时不复用逐字节比较结果。
7. 根据介质类型限制并发：旋转硬盘优先顺序读，SSD 可增加并发；用户可暂停和续扫。

## 7. keeper 与 time donor 解耦

### 7.1 keeper 选择

keeper 默认按以下顺序评分，但最终建议必须展示理由且允许用户覆盖：

1. 当前完整可读、执行前验证通过；
2. 位于用户标记的优先保留目录；
3. 逻辑资产更完整，伴随文件关系无歧义；
4. 独有的 xattr、Finder 标签、ACL 或 resource fork 更完整；
5. 文件名更接近原始命名；
6. 文件系统时间与高置信度拍摄时间一致；
7. 路径更短或更符合用户设定的归档规则。

同一底层数据的硬链接或克隆文件必须单独标识，不能把逻辑副本数直接等同于物理空间节省量。

### 7.2 时间证据

产品内部必须分别保存：拍摄时间、文件创建时间、文件修改时间、原始文本、解析后的时区/偏移、精度和来源。不得把 Finder“添加日期”静默当成拍摄时间。

| 证据 | 默认置信度 | 说明 |
| --- | --- | --- |
| EXIF `DateTimeOriginal` + 时区/亚秒 | 高 | 合法且与媒体结构一致时可自动建议 |
| QuickTime 创建时间与轨道时间交叉一致 | 高 | 需处理 UTC 与本地时间语义 |
| 已可靠绑定的 XMP/导出 JSON | 中至高 | 必须证明归属，不能只靠模糊文件名 |
| 重复组中较早的 birthtime/mtime，且获文件名或相邻照片佐证 | 中 | 默认需确认 |
| 文件名、父目录日期或单独一个文件系统时间 | 低 | 只展示，不自动写回 |

以下情况必须降级为冲突或低置信度：非法日期、1970/1980/1904 等哨兵值、明显未来时间、批量文件共享同一复制时间、强证据不一致、整数小时偏差疑似时区问题、无时区且无法推断地点。重复副本数量不能被当作独立证据数量。

### 7.3 donor 迁移规则

1. 先选 keeper，再独立选 time donor；界面分别展示两者。
2. 默认仅建议修复 keeper 的文件创建时间和/或修改时间，不改媒体内容。
3. 写入前记录旧值和证据，写入后按该卷的实际时间精度读回验证。
4. 如果创建时间不可写，可明确降级为“仅修复修改时间”或“仅生成报告”；不得把 mtime 冒充 birthtime。
5. 写回失败、精度损失超出已知舍入范围或证据冲突时，donor 保留原位且整组不自动隔离。
6. 写入 EXIF/QuickTime/XMP 属于后续高级模式，必须创建新内容版本并重新哈希，不得悄悄改写原文件。

## 8. 产品流程与界面信息架构

### 8.1 首次使用

1. 解释“默认只读、不会直接删除”和隔离区不是备份。
2. 用户选择扫描根目录；产品显示卷、文件系统、读写状态和能力等级。
3. 默认排除 `.photoslibrary`、归影隔离区、系统目录、包内容、隐藏挂载点和用户新增排除项。
4. 用户确认后开始只读扫描。

### 8.2 主导航

- **概览**：扫描进度、候选数量、可确认节省空间、异常与卷状态；
- **确定重复**：D1 组，支持逐组审阅和批量采用安全建议；
- **画面相同/相似**：D2/D3 候选，始终人工处理；
- **时间问题**：建议时间、来源、置信度、时区与冲突；
- **异常与跳过**：损坏、权限、占位符、变化中、未知资产等；
- **隔离区**：事务、原路径、恢复状态和保留期限；
- **活动与报告**：执行计划、日志、错误、导出和恢复入口；
- **设置**：优先目录、排除规则、性能、时间策略和隐私。

### 8.3 关键交互约束

- 执行按钮旁必须显示“将隔离 N 个文件、修复 M 个时间、跳过 K 个风险项”，不能只显示节省空间。
- 操作预览必须列出 keeper、time donor、伴随资产、原路径、目标路径和变更前后时间。
- 风险项不得被“全选”隐式纳入；用户确认也不能绕过工程层面的禁止条件。
- 扫描和哈希可暂停；掉盘后状态显示“等待原卷”，不得把同名卷当作原卷。
- 恢复永不覆盖现有不同内容，应恢复至独立安全路径并提示冲突。
- 永久清理是独立入口，MVP 中默认关闭；未来启用时需再次验证 keeper 和独立确认。

## 9. 功能需求与验收标准

### FR-01 目录选择与范围控制

- 支持选择一个或多个扫描根目录，检测重叠根目录并去重。
- 不跨越嵌套挂载点，除非用户显式将其作为独立根目录加入。
- 默认排除隔离区、`.photoslibrary` 和应用内部目录。

**验收：** 同一文件不会因重叠根目录被扫描两次；嵌套卷不会继承父卷执行计划。

### FR-02 卷识别与能力展示

- 显示卷身份、文件系统、挂载方式、只读状态和实际探测得到的能力等级。
- 重新挂载、驱动变化或身份不一致时使旧执行计划失效。

**验收：** 同名替换硬盘不能继续原计划；未知或只读卷只能生成报告。

### FR-03 增量精确扫描

- 实现第 6.2 节流水线、暂停、继续和断点续扫。
- 扫描过程中读取失败或变化的文件进入异常列表，不阻塞其他只读扫描。

**验收：** 对测试集的 D1 召回率与准确率均为 100%；任何非 D1 文件都不进入自动隔离计划。

### FR-04 逻辑资产识别

- 识别 Live Photo、AAE、XMP、JSON、THM 和 AppleDouble 候选绑定关系。
- 关系有歧义时整组禁止自动隔离。

**验收：** 已知 Live Photo/sidecar 组合不会留下孤儿；模糊匹配不会触发自动处理。

### FR-05 keeper 建议

- 按第 7.1 节生成可解释建议；用户可指定优先目录并逐组覆盖。

**验收：** 建议结果可重复；报告中能追溯所有评分和用户覆盖。

### FR-06 时间分析与 donor 建议

- 提取并保留时间的原始值、语义、精度、时区、来源和置信度。
- 标出批量复制时间、异常值和冲突，不按副本数投票。

**验收：** 预置的 DST、无时区、整数小时偏差、非法日期和复制时间样本均进入预期状态。

### FR-07 执行预演

- 在任何写操作前生成冻结计划，重新验证卷身份、文件身份、大小、时间快照、完整哈希和逐字节一致性。
- 显示预计逻辑释放空间与可能的实际释放空间差异。

**验收：** 扫描后被修改或替换的文件不会执行；APFS clone/硬链接不会虚报实际释放空间。

### FR-08 时间修复

- 仅在能力探测和证据规则允许时写入文件时间；写后读回。
- time donor 的迁移未提交前不允许隔离 donor。

**验收：** 注入不支持 birthtime、时间舍入、写后值不一致时，系统分别正确降级并保留 donor。

### FR-09 隔离与事务恢复

- 安全条件满足时仅移动到同卷专属隔离区，不永久删除。
- 每个文件采用可重入事务状态机；应用崩溃、睡眠、掉盘后可恢复。

**验收：** 在每个事务状态点强杀进程后重启，状态可确定收敛且至少保留一份已验证内容。

### FR-10 幂等恢复

- 可按单项、重复组或事务恢复；恢复目标不得覆盖现有不同内容。
- 重复执行恢复产生相同安全结果。

**验收：** 原路径空、相同文件存在、不同文件存在及恢复中崩溃四类场景均通过。

### FR-11 审计与导出

- 导出 JSON 和 CSV，包含规则版本、卷身份摘要、路径、哈希、keeper、donor、证据、状态、错误及时间变更。
- 默认不联网；诊断导出允许用户预览并脱敏路径。

**验收：** 任一已提交操作都能从报告还原“为何处理、处理了什么、结果如何”。

## 10. 非功能需求

### 10.1 安全

以 [SAFETY.md](../engineering/SAFETY.md) 为强制规范；安全门槛不可由 UI 或配置绕过。P0 发布门槛未全部通过时，产品只能提供只读扫描。

### 10.2 性能

- 对非重复文件，尽量只执行元数据读取和大小分桶；
- 哈希使用流式 I/O，内存占用不随单文件大小线性增长；
- 默认后台并发不能使机械硬盘持续随机寻道或让界面失去响应；
- 百万级索引能够增量恢复，不要求单次驻留内存。

具体性能目标应在基准硬件和真实照片语料建立后冻结；在此之前不得用未经测量的速度作为宣传承诺。

### 10.3 隐私与安全解析

- 所有照片和索引默认仅保存在本机，不上传、不调用在线识图；
- 缩略图与元数据解析运行于无网络、有限内存和超时约束的隔离进程；
- 哈希扫描不依赖媒体解析器，解析器失败不能改变 D1 判定；
- 日志不记录照片内容，诊断包默认脱敏用户路径。

### 10.4 可访问性

- 不仅用颜色表达置信度和错误；
- 所有核心操作可键盘完成，并提供 VoiceOver 标签；
- 风险确认文字使用明确对象与动作，不使用模糊的“确定/继续”。

## 11. 成功指标

### 11.1 安全指标

- 已知 D1 测试集自动隔离误判数：0；
- 故障注入中违反“至少一份已验证完整内容”不变量次数：0；
- 无审计记录的文件变更次数：0；
- time donor 未安全迁移即被隔离次数：0。

### 11.2 产品指标

- 用户能在执行前准确回答“保留哪个、时间来自哪里、会移动什么”；
- 第二次扫描仅处理新增或变化文件；
- 隔离和恢复的最终状态可解释、可重复；
- 异常项都有明确原因和下一步建议，不出现静默跳过。

## 12. MVP 发布验收

只有同时满足以下条件，才允许从“只读预览版”升级为“可隔离版”：

1. D1 判定、执行前复核与并发变化检测完成并通过测试；
2. 文件系统能力探测与 [FILESYSTEMS.md](../engineering/FILESYSTEMS.md) 的降级矩阵落实；
3. 双份持久化事务记录、状态恢复和幂等恢复完成；
4. 所有 [SAFETY.md](../engineering/SAFETY.md) P0 故障注入门槛通过；
5. Live Photo/sidecar 歧义、特殊文件、云端占位符和跨卷操作均能 fail closed；
6. 时间写回在目标文件系统上完成写后读回验证，失败时 donor 不被移动；
7. 执行报告覆盖所有文件变化，且 UI 无法绕过禁止条件；
8. 在真实外置硬盘副本上完成不少于两轮完整演练和恢复演练。
