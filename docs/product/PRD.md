## 1. 产品定义

归影是一款帮助个人整理本地照片和视频重复副本的 macOS 工具。它的第一个可用版本只处理“每个字节都相同”的确定重复，让用户决定留下哪份，并把其他副本移入同一卷上可恢复的隔离区。

一句话承诺：**只整理已证明完全相同的副本，每次移动都先给你看清，并且可以恢复。**

归影不把“发现了重复”当成用户结果。用户结果是：不需要理解哈希、封印或文件系统术语，就能完成一次有明确保留项、可预览、可撤回的整理。

## 2. 为什么重做产品范围

重设计前的实现能可靠地证明哪些文件内容相同，但用户到达结果页后无法决定保留项，也无法看到真正的整理计划。报告格式、证据范围和路径脱敏成了页面主操作，却不能推动整理。本轮已修正这个产品死胡同，但在写入安全协议完成前，标准构建仍只读。

本版重新排序：

1. 首先打通最窄但真实的整理闭环；
2. 只在用户需要解释时展示技术证据；
3. 报告是活动记录中的次要能力，不是必经流程；
4. 没有实现的后续能力不作为锁定步骤展示；
5. 任何不确定都归入“为安全保留”，用户不能通过确认绕过工程禁止条件。

## 3. 用户与需要完成的任务

### 3.1 主要用户

长期把手机照片多次复制到 Mac 或外置硬盘的个人用户。他们知道“重复很多”，但不愿为理解 BLAKE3、descriptor、mount session 或时间元数据冒丢照片的风险。

### 3.2 核心作业

> 我想知道哪些是真正重复的文件，选择要留下的一份，在看清会发生什么后把其他副本移开；如果选错了，我要能找回来。

### 3.3 完成标准

用户不导出 JSON/CSV、不打开原始证据，也能：

- 找到可处理的确定重复组；
- 知道每组保留哪个、移走哪些；
- 在执行前看到准确文件数、位置和风险跳过数；
- 完成一次隔离，随后按项、按组或按本次活动恢复；
- 理解“隔离不是删除，同卷移动也不会释放空间”。

## 4. 首个真实闭环

### 4.1 步骤 1：选择照片位置

- 用 macOS 原生目录选择器获得一次可读授权；
- 默认排除归影隔离区、`.photoslibrary`、包内容、系统目录与嵌套挂载点；
- 首屏只解释当前动作：“先扫描，不会移动照片”；
- 扫描前不要求用户选择报告格式、证据级别或路径投影。

### 4.2 步骤 2：扫描

- 默认只显示“正在查找完全相同的文件”、已检查数、待检查数和耗时；
- 允许同一次打开中暂停、继续和停止；退出后不宣称能从原位继续；
- 把大小分桶、抽样、BLAKE3 和逐字节比较收在“如何确认？”详情中；
- 单文件不可读、扫描中变化或解析失败时跳过并保留，不阻塞其他只读扫描。

### 4.3 步骤 3：选择保留项

- 结果默认分成“可整理”和“为安全保留”，而不是按技术证据类型导航；
- 每个可整理组显示一个系统建议的保留项，并用人话解释，例如“位于你的优先目录”或“文件名未被追加序号”；
- 组内文件只有两种当前决策：**保留原位**或**移入隔离区**；
- 可批量接受建议，但只能包含已通过工程安全门的组；
- 系统建议不是自动执行。用户可以更换保留项、整组暂不处理，或查看高级证据；
- 没有明确保留项的组不能进入预览。

### 4.4 步骤 4：预览本次整理

预览是用户决策页，不是技术报告。必须首先显示：

- 保留在原位的文件数；
- 将移入隔离区的文件数和逻辑大小；
- 为安全保留、不执行的组数及原因；
- 隔离区所在卷，以及“不是删除、暂不释放空间”的明确说明；
- 任一文件在扫描后变化、卷身份改变或能力探测失效时，该项不执行并回到复核状态。

主操作文案必须包含对象和动作，例如“将 34 个副本移入隔离区”，不使用模糊的“应用”或“继续”。

### 4.5 步骤 5：可恢复隔离

- 只在目标卷完成 C3 能力探测、冻结计划已持久化且执行前复核通过时开始；
- 只把已选为“移入隔离区”的副本移到同卷归影隔离区；
- 进度界面用“已移动 / 已跳过 / 需对账”表达真实状态，不用动画掩盖持久化和验证；
- 任一 I/O、权限、容量、身份或日志异常会停止当前卷的后续写入；
- 完成页必须提供“查看隔离区”和“恢复本次移动”，而不是把用户送回报告导出。

### 4.6 步骤 6：恢复

- 用户可按单项、重复组或一次整理活动发起恢复；
- 恢复前预览原路径、实际恢复路径、冲突和已不可用项；
- 原路径已有不同内容时绝不覆盖，恢复到卷上独立安全目录并告知用户；
- 恢复中断后可重试，重复执行得到相同安全结果；
- 恢复后的活动记录保留原计划、实际结果与冲突处理。

## 5. 第一版可处理边界

### 5.1 可进入隔离计划的组

首版只处理同时满足以下条件的组：

1. 内容是 D1 字节完全相同，扫描时已逐字节确认；
2. 已明确选定一个 keeper，至少一份已验证完整内容保留在原位；
3. 文件是当前可读的普通文件，位于同一可识别卷；
4. 没有模糊的 Live Photo、AAE、XMP、JSON、AppleDouble 等伴随关系；
5. 没有无法安全合并的独有 xattr、ACL、resource fork 或其他逻辑资产差异；
6. 既有策略未把非 keeper 成员标记为必须先迁移信息的 time donor；此类组在本版整组保留；
7. 卷身份、挂载代次、持久化日志、空间预算与 no-replace 同卷移动能力均通过。

上述条件是工程授权，不是用户风险确认。用户不能通过“我了解风险”强行加入计划。

### 5.2 只读证据的位置

现有拍摄时间证据、原始字段、哈希和逐字节验证保留为“为什么这些是重复？”与“为什么这组暂时不能处理？”的高级详情。它们不再占据主导航、主标题或主操作区。

本版不选择 time donor，不迁移时间，不写入 birthtime/mtime，不改写 EXIF/QuickTime/XMP。被隔离文件的扫描时间证据会进入活动记录，但不被宣称为已修复或已合并。

## 6. 信息架构

主导航从“工程阶段”改为“用户可到达的地方”：

- **整理**：选目录、扫描、保留决策、预览、执行与完成；
- **隔离区**：已移动项、原路径、隔离时间、状态、恢复与冲突；
- **活动**：扫描和执行历史、异常、只读证据与可选导出；
- **设置**：优先保留目录、排除规则、扫描性能和隐私选项。

不显示尚未实现的“时间修复”“相似照片”或“永久删除”导航项；不使用“Phase 1”或锁定流程向普通用户展示开发计划。

## 7. 功能需求与验收

### FR-01 目录选择与范围

- 支持选择一个普通目录；多根目录继续作为后续扩展；
- 检测隔离区、包、嵌套卷与不可用权限；
- 目录授权过期或挂载变化时引导重新选择。

**验收：** 用户从首屏可在一个主按钮后进入扫描；不需要先理解导出或证据设置。

### FR-02 只读 D1 扫描

- 保留大小分桶、分段指纹、完整 BLAKE3 与逐字节确认主链；
- 支持同进程暂停/继续与取消；
- 不在主进度中要求用户辨认算法阶段。

**验收：** 基准语料 D1 召回率与准确率均为 100%；任一非 D1 文件都不进入可整理列表。

### FR-03 可处理资格分类

- 对每组生成 `eligible`、`review_required` 或 `blocked` 结论；
- 结论同时有稳定机器码和面向用户的原因；
- 任一未知或冲突只会减少可处理数。

**验收：** 给定相同证据时分类结果可重复；界面能回答“为什么这组暂时不能移动？”。

### FR-04 keeper 决策

- 为可处理组提供可解释建议；
- 每组必须且只能有一个 keeper；
- 用户切换 keeper 时，其余成员的 Move 计划同步更新；
- 整组可设为暂不处理。

**验收：** 任一计划项的 keeper 必定属于该组且不在隔离候选中；未确认决策不被冒充为已执行。

### FR-05 执行预览

- 根据最新决策编译不可变计划；
- 展示 Keep/Move 数、跳过数、逻辑大小、卷与隔离目标；
- 预览与实际执行的差异必须记录为跳过或失效，不静默换入新文件。

**验收：** 用户能在执行前准确复述三件事：留哪些、移哪些、哪些因风险不动。

### FR-06 同卷隔离

- 实现 [SAFETY.md](../engineering/SAFETY.md) 与 [FILESYSTEMS.md](../engineering/FILESYSTEMS.md) 的 C3 授权、双份耐久记录、执行前复核和 no-replace 移动；
- 实际隔离文件重新打开并验证；
- 异常后停止当前卷，并保留可对账状态。

**验收：** 在每个事务状态点强制终止进程，重启后不违反 Last-good-copy，且不出现无审计的用户文件变更。

### FR-07 恢复与对账

- 支持单项、组和活动恢复；
- 不覆盖原路径的不同内容；
- 应用崩溃或掉盘后，通过本机记录、卷上清单与文件实物对账。

**验收：** 原路径为空、已有相同内容、已有不同内容与恢复中崩溃四类场景均可重复收敛。

### FR-08 活动与报告

- 活动首先以人可读方式展示本次计划、结果、跳过和恢复；
- JSON/CSV 导出放在活动的次要菜单，保留脱敏选项；
- 导出成功不改变整理状态，导出失败不阻止隔离或恢复完成。

**验收：** 每个已提交文件操作都能解释“为什么处理、计划做什么、实际发生什么、如何恢复”。

### FR-09 可访问性与文案

- 核心闭环可以用键盘和 VoiceOver 完成；
- Keep/Move、禁止、成功和冲突都至少使用文字/图形与色彩两种信号；
- 普通界面不使用“封印”“descriptor-bound”“mount session”或“逻辑重复上限”作为主文案。

**验收：** 在 1024 × 768 窗口、200% 文本放大和简体中文/中英混排下，主操作仍可达；至少完成一轮 VoiceOver 真机走查。

## 8. 明确不做

以下能力不在首个真实闭环的计划和导航中：

- 永久删除或自动清空隔离区；
- 修复 birthtime/mtime，或改写 EXIF、QuickTime、XMP 内容；
- D2 解码画面相同与 D3 模糊/视觉相似；
- 凭文件名、日期、文件大小、快速指纹或缩略图自动移动；
- 直接修改 Apple Photos `.photoslibrary` 或云端目录；
- 跨卷复制完成后自动删除源文件；
- 网络识图、人脸识别、相册编辑和归档重命名。

将来如果重新评估任一项，必须作为独立产品决策和安全评审，不得通过“高级选项”混入本闭环。

## 9. 非功能需求

### 9.1 安全与事务

- [SAFETY.md](../engineering/SAFETY.md) 仍是写入授权的强制规范；
- 核心策略层授权每个项目，前端不能仅凭开关或确认文案绕过；
- 隔离、恢复和对账是独立可重入操作；
- 隔离区不是备份，但首版也不会删除其中的文件。

### 9.2 隐私

- 照片、索引、缩略图和活动记录默认只在本机；
- 无默认网络上传、遥测或在线解析；
- 路径在报告中默认脱敏，但在本机决策页要以用户可区分的方式显示。

### 9.3 性能与响应

- 哈希使用流式 I/O，单文件内存不随文件大小线性增长；
- 转盘和 SSD 采用不同并发策略，不为追求页面进度造成持续随机寻道；
- 长任务不阻塞导航、停止或安全退出；
- 在有真实基准前不宣传未经测量的扫描速度。

## 10. 产品成功指标

### 10.1 闭环可用性

- 首次使用者在不打开高级证据的情况下，能完成一次“选择保留项 → 预览 → 隔离 → 恢复”测试任务；
- 用户在执行前能说清 Keep、Move、Skip 各自的含义；
- 结果页不再出现“看起来完成但没有下一步”的终点；
- 报告导出使用率不被当成整理成功率。

### 10.2 数据完整性

- D1 隔离误判数：0；
- 违反 Last-good-copy 次数：0；
- 覆盖不同内容次数：0；
- 无耐久审计的文件变更数：0；
- 已验证隔离项的恢复任务成功或明确安全冲突率：100%。

本项目不接入默认上传型遥测。用户可用性指标通过本地合成场景、专用测试卷与授权研究会话验证。

## 11. 首个可隔离版发布门槛

以下条件必须全部满足，才能面向用户显示可执行的隔离按钮：

1. 选择 keeper、暂不处理和批量接受建议的状态模型可持久化、可审计；
2. 不可变计划编译器只接受第 5.1 节的可处理组；
3. 卷身份、挂载代次、C3 能力探测、空间预算和执行前 D1 复核完成；
4. 本机数据库与卷上 append-only 清单的双份耐久意图可对账；
5. 隔离与恢复状态机在每个注入故障点都不违反 [SAFETY.md](../engineering/SAFETY.md) 的 P0 不变量；
6. APFS、HFS+ 与 exFAT 专用真实外置测试卷的支持范围通过掉盘、重挂、同名换盘、写满和崩溃恢复演练；
7. 恢复入口在隔离成功页和主导航中同时可达，且完成 VoiceOver 真机走查；
8. 界面没有永久删除、时间修复或 D2/D3 操作入口，也不把同卷隔离宣称为已释放空间。

开发顺序、依赖与每个里程碑的出口条件见 [ROADMAP.md](../ROADMAP.md)。
