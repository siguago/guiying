## 1. 路线图的完成定义

归影不能再以“又完成了一层证据”或“又增加了一个只读页面”作为产品完成。首个版本只有在真实用户无需导出报告、无需理解底层校验术语，就能完成并撤销一次重复文件整理时才算完成。

首个真实闭环只包含：

1. 选择一个普通目录；
2. 扫描 D1 字节完全相同的文件；
3. 为安全合格的组选择唯一保留项；
4. 预览 Keep、Move 与 Skip；
5. 把 Move 项移动到同卷可恢复隔离区；
6. 从隔离区按项、按组或按活动恢复。

永久删除、时间修复、D2 画面相同和 D3 视觉相似不属于这条路线。它们没有隐藏入口、占位步骤或承诺日期。

## 2. 当前产品事实与缺口

### 2.1 已完成的可信基础

- 原生目录选择与窗口绑定的一次性根授权；
- 无主动照片变更的流式扫描，大小分桶、抽样、完整 BLAKE3 与逐字节 D1 定案；
- descriptor/mount 夹持、不可构造读取证明、卷与扫描阶段封印；
- SQLite 安全迁移、历史 catalog、有界分页和窗口绑定的 result token；
- 同一进程、同一次打开中的枚举暂停/继续与合作式取消；
- 重新选择根后的 v9 fresh-attempt：精确唯一候选建立全新全量 child，零候选或歧义建立独立 initial job，不恢复旧权限、游标或证据；
- 只读拍摄时间和文件系统时间证据；这些证据不会直接授权写入；
- JSON/CSV 历史报告导出，默认路径脱敏；
- Rust/Tauri/React 自动化门禁、WebKit UI 覆盖和安全契约测试。

### 2.2 用户闭环缺口

| 用户要完成的事 | 当前状态 | 用户后果 | 计划里程碑 |
| --- | --- | --- | --- |
| 选择目录 | 已实现 | 可开始扫描 | M1 简化入口文案 |
| 找出确定重复 | 已实现 | 能看到 D1 结果 | M1 隐藏非必要术语 |
| 选择保留哪份 | 已实现单组决策 | 可明确一个 keeper | M2 继续补跨组草稿 |
| 看清会移动什么 | 已实现单组只读预览 | 标准构建可看 Keep/Move，不执行 | M2 |
| 移入可恢复隔离区 | 未实现 | 整理没有发生 | M3 |
| 反悔并恢复 | 未实现 | 无法形成可信闭环 | M4 |
| 导出报告 | 已实现 | 只能留下一份技术记录 | M1 降为活动次要操作 |

现有数据库中的 operation、quarantine、restore 等表和约束是受测试的安全契约，不是可执行写能力。前端的锁定步骤也不是路线进度；在相应命令、安全策略和恢复门禁完成前，不得把它们描述为即将可用的用户操作。

> 命名迁移：部分历史工程文档仍用 “Phase 1” 表示只读运行时、用 “M2/M3 写能力”泛指未来写入。它们的技术约束继续有效，但里程碑编号不再对应本路线图；新计划以本文件的 M0–M5 为准，写入引擎是 M3，用户可发布的隔离/恢复闭环是 M4。

### 2.3 当前仍需真实介质证明的基础

- APFS、HFS+ 与 exFAT 外置卷的拔插、重挂、同名替换与克隆 UUID；
- 掉盘、写满、短读写、权限变化和睡眠恢复；
- 当前应用 bundle/native-run、系统目录对话框与 VoiceOver 真机流程；
- 不可靠卷上的持久化清单、目录 fsync 与 no-replace 行为。

自动化临时卷测试不能替代这些门槛。

## 3. 排序原则

1. **用户闭环优先于证据宽度。** 已能安全判定 D1 后，下一项工作是 keeper 与恢复，不是 D2/D3 或更多时间解析。
2. **先建立选择，再建立写入。** keeper 与计划预览先以只读方式落地，稳定后再接隔离执行。
3. **恢复与隔离是同一发布单元。** 没有用户可达的恢复，不开放隔离。
4. **工程门禁不交给用户确认。** 不合格组只会进入 Skip/为安全保留。
5. **界面只展示真实可到达能力。** 不显示锁定的未来步骤，不用开发阶段名做用户导航。
6. **报告不阻断主任务。** 导出保留，但不能成为扫描后的主操作。
7. **安全核心继续 fail closed。** 任一 P0 未通过时，产品保持或回退到只读。

## 4. 发布通道

| 通道 | 用户可见能力 | 使用边界 |
| --- | --- | --- |
| Internal | 选择、预览、故障注入、实验性隔离/恢复 | 专用可破坏测试卷 |
| Preview Read-only | 目录选择、D1 扫描、结果复核、历史与导出 | 不改变用户照片 |
| Closed Beta Reversible | 受支持卷上的 D1 keeper、预览、同卷隔离与恢复 | 有独立备份、明确支持矩阵 |
| Stable Reversible | 支持矩阵内的 D1 扫描、隔离、恢复和活动记录 | 普通用户；仍无永久删除与时间修复 |

功能旗标只能关闭能力，不能打开尚未通过核心策略和发布门槛的能力。

## 5. M0：只读证据基础

**状态：已完成主体；真实外置卷验证仍在进行。**

### 用户结果

用户可以选择目录、执行无主动变更的 D1 扫描、查看结果和历史，并导出报告。

### 已交付

- 只读扫描主链、D1 完整证据、错误与跳过；
- 同进程暂停/继续/停止；
- 历史只读目录、分页证据与 JSON/CSV 导出；
- 只读时间证据和元数据原始字段；
- 本机 SQLite、进程级互斥、owner-window 边界和 IPC 契约；
- 安全、数据模型、文件系统和捕获时间规范。

### 保持锁定

- keeper 与 Move 决策；
- 冻结执行计划；
- 任何照片移动、改名、改时或删除；
- 隔离和恢复。

M0 的技术能力继续作为后续里程碑的安全输入，但不再决定页面主结构。

## 6. M1：产品表面重置

**状态：本轮已完成产品表面基线；发布通道仍以门禁结果为准。**

### 用户结果

用户不会再在结果页遇到一个看似可继续、实际永远锁定的步骤；扫描的用途、边界和下一步状态都清楚。

### 交付物

- 主导航改为“整理 / 隔离区 / 活动 / 设置”的目标结构；在隔离功能未交付前，隔离区入口只在开发/测试构建中出现；
- 当前只读发布不展示“隔离执行”锁定步骤、Phase 编号或未来能力；
- 首屏收敛为“选择目录并扫描”，移除与当前任务无关的技术凭证；
- 扫描主进度使用用户语言，算法阶段折叠到“如何确认？”；
- 结果页把 D1 组放在主任务，把时间证据、原始哈希和逐字节链路放入按需详情；
- 报告导出移动到历史/活动的次要操作，不再占据结果页主操作区；
- 空、加载、暂停、取消、错误和权限过期状态都给出明确下一步。

### 退出条件

- 用户不会把导出报告误认为照片已整理；
- UI 不出现未实现动作的可点击入口或锁定流程承诺；
- 浏览器与 Tauri 入口均保持现有只读安全边界；
- 键盘顺序、焦点恢复、axe 与 1024 × 768 紧凑布局通过；
- 现有只读后端契约、报告导出和历史读取测试全部回归通过。

## 7. M2：Keeper 决策与只读预览

**状态：本轮完成单组 keeper、Keep/Move 与预览；跨组服务端草稿、批量安全建议和 revision/stale 收敛仍在本里程碑内。**

### 用户结果

用户可以为可处理的重复组决定“保留哪份、将来移动哪些”，并看到一份不会执行写入的准确预览。

### 产品与前端

- “可整理 / 为安全保留”结果分区；
- 每组唯一 keeper、系统建议理由、用户覆盖和“整组暂不处理”；
- Keep/Move 双轨成员控件；
- 只对 `eligible` 组提供批量接受安全建议；
- 粘性决策摘要：Keep、Move、Skip、逻辑大小；
- 预览页列出原路径、隔离目标、组级阻断和“不释放空间”说明；
- 计划过期、文件变化或卷变化后返回对应组复核，不清空其他有效决策。

### 核心与持久化

- 可处理资格分类器：普通文件、D1 证据、逻辑资产、独有元数据、donor、卷和权限；
- keeper 建议器只输出理由和候选，不直接授权执行；
- keeper/skip 用户选择持久化与审计；
- 不可变 dry-run 计划编译器，绑定扫描、卷、挂载代次、组、keeper 和候选；
- 计划摘要与每个阻断原因的稳定机器码；
- 前后端共享 DTO 与运行时拒绝测试。

### 退出条件

- 任一计划组必须恰好一个 keeper，keeper 不能同时是 Move 项；
- 非 D1、跨卷、歧义资产、独有元数据、非 keeper donor 与变化中文件都不会进入计划；
- 同一输入产生相同建议和分类；用户覆盖可追溯；
- 预览中的文件数与计划项逐项一致；
- 前端无法伪造 eligible、keeper、目标路径或卷能力；
- UI 明确标记“预览不会移动文件”，没有执行按钮。

## 8. M3：隔离事务引擎

**状态：内部实验引擎已有单组同卷 no-replace 与清单恢复原型，但尚不满足完整 `SAFETY.md` 写入协议。Cargo feature 默认关闭，标准 macOS 构建与前端都 fail closed；不得用环境开关把它当成发布能力。**

### 用户结果

在专用测试卷上，已确认 Move 项可以安全进入同卷隔离区；任何中断都会停止并留下可对账状态。

### 卷与能力

- 将 C3 探测实现为运行时事实，而不是文件系统名称白名单；
- 绑定卷身份、挂载代次、驱动/能力版本和空间预算；
- 创建归影专属隔离区、探测目录和卷上 append-only manifest；
- no-replace 同卷 rename；不满足时首版直接保持只读，不启用复制后删源 fallback；
- 每次执行前重新打开并验证 source、keeper、完整 BLAKE3 与逐字节一致性。

### 计划与执行

- dry-run 计划提升为用户确认的 sealed batch；
- 本机 SQLite outbox 与卷端 manifest 的双份耐久 intent；
- item 级可重入状态机与卷级写入熔断；
- 隔离目标读回、完整内容验证和不可变事件；
- 进程启动与卷重新挂载时对账；
- 取消只影响尚未开始的项，不能把状态倒退。

### Internal UI

- 执行确认显示明确 Move 数量和隔离卷；
- 真实进度使用“准备 / 已移动 / 已验证 / 已跳过 / 需对账”；
- 卷拔出、空间不足、权限变化、文件变化和 manifest 分歧都有专门恢复文案；
- 执行中不提供永久删除或“释放空间”表述。

### 退出条件

- [engineering/SAFETY.md](./engineering/SAFETY.md) 隔离相关 P0 故障注入全部通过；
- 在每个状态转换前后强杀进程不违反 Last-good-copy；
- 短读写、写满、日志刷盘失败、权限变化和卷变只读触发卷级停止；
- 同名换盘、TOCTOU、symlink 置换和并发变化均拒绝执行；
- 本机记录、卷上 manifest 与文件实物分歧只会进入对账，不会猜测或覆盖；
- Internal 专用 APFS、HFS+、exFAT 测试矩阵有可复现记录。

M3 不单独面向用户发布；必须与 M4 的恢复入口和恢复门禁一起进入 Closed Beta。

## 9. M4：恢复与 Closed Beta 闭环

**状态：内部 feature 已有清单驱动的单组恢复命令，前端也已实现不依赖当次扫描内存的独立恢复入口；但标准构建仍默认锁定。双份日志、崩溃/启动对账、完整冲突策略与真实介质演练全部通过后才能进入 Closed Beta。**

### 用户结果

用户可以从完成页或“隔离区”找回本次移动的文件；原路径冲突时归影保留双方并清楚说明实际位置。

### 交付物

- 隔离区列表、按活动/组/项浏览和原路径信息；
- 单项、组、整次活动的恢复预览；
- no-replace 原路径恢复；
- 已有相同内容时幂等完成，已有不同内容时恢复到 `Recovered/<transaction-id>/`；
- 恢复 item 状态机、卷端 manifest 记录、崩溃恢复与重新挂载对账；
- 隔离成功页直接提供“恢复本次移动”；
- 活动记录展示计划、实际移动、跳过、对账和恢复；
- 面向 Closed Beta 的支持矩阵、限制和独立备份说明。

### 退出条件

- 原路径为空、已有相同内容、已有不同内容、恢复中崩溃、掉盘和重挂全部通过；
- 重复恢复得到相同安全结果，不覆盖不同内容；
- 任一已移动项可从完成页和隔离区找到恢复入口；
- 用户测试可以在不打开高级证据或导出报告的情况下完成全闭环；
- 用户能准确解释“隔离不是删除，也不会释放空间”；
- VoiceOver、键盘、200% 文本和高对比度真机流程通过；
- APFS、HFS+、exFAT 的真实外置卷支持范围通过两轮完整隔离与恢复演练。

## 10. M5：稳定版收敛

**状态：M4 之后。只做闭环质量，不扩展问题类型。**

### 交付物

- 大型目录性能、机械硬盘顺序读和长任务响应优化；
- keeper 建议理由与“为安全保留”原因的可理解性迭代；
- 活动和隔离区的大数据分页、搜索与筛选；
- 权限过期、卷不在、计划失效和对账队列的恢复体验；
- 崩溃报告和诊断包的本地预览与路径脱敏；
- 完整 macOS 支持版本、文件系统/驱动支持矩阵；
- 升级、数据库迁移和旧 Preview 历史结果兼容。

### Stable 退出条件

- 没有未关闭的 P0/P1 数据完整性问题；
- P0 故障矩阵、真实介质矩阵和用户闭环回归持续通过；
- 可访问性与内容压力测试没有阻断问题；
- 发布文案不承诺永久删除、时间修复、空间释放或模糊相似；
- 从 Preview 升级不会把旧证据或旧路径静默提升为写授权。

## 11. 横向工作流

### 11.1 产品与内容

- 每个里程碑都从用户能完成的任务定义，不从数据库表或算法名定义；
- 用户文案遵循“对象 + 动作 + 后果 + 恢复方式”；
- 每个错误说明哪些文件未改变、下一步是什么；
- 不把内部 Phase、seal、token、descriptor 或 fingerprint 作为普通流程词汇；
- 每轮用户测试至少覆盖一位不了解哈希与文件系统的人。

### 11.2 安全策略与存储

- UI、IPC、runtime、store 和 SQLite 触发器形成多层拒绝；
- sealed batch 一经用户确认不可原地修改，变化后生成新计划；
- 任何写能力必须同时有正常、禁止、fallback、崩溃和恢复测试；
- append-only 事件不可通过清空错误或直接修改状态“修复”；
- dormant schema 不计作可交付功能。

### 11.3 测试语料与介质

- 合成 D1、非 D1、快速指纹碰撞、扫描中替换和路径身份夹具；
- 独有 xattr/ACL/resource fork、Live Photo/sidecar 歧义和 donor 阻断夹具；
- 专用 APFS、HFS+、exFAT 外置盘，不使用用户唯一照片做破坏性测试；
- 系统调用层 EIO、ENOSPC、权限、短读写、延迟和进程强杀；
- 每个缺陷增加最小回归夹具和用户可见错误文案。

### 11.4 隐私、可观测性与无障碍

- 默认日志、截图和诊断导出不包含照片内容与未脱敏路径；
- 不接入默认上传遥测；未来任何遥测必须另行 opt-in 评审；
- 所有核心操作有键盘、可见焦点、VoiceOver 名称和状态公告；
- 重要状态不用颜色单独表达；
- 至少覆盖 1024 × 768、窗口缩放、200% 文本、简体中文和中英混排。

## 12. 明确延期且不排期

以下能力不在 M1–M5：

- 自动或手动永久删除隔离区内容；
- birthtime/mtime 修复与 EXIF/QuickTime/XMP 写回；
- D2 解码画面相同；
- D3 感知哈希、向量或其他模糊相似；
- `.photoslibrary` 修改、云端直接清理、跨卷复制后删源；
- 目录重组、批量改名、人脸识别和图像编辑。

现有只读时间证据可以继续用于解释和阻断，但不得驱动写入。上述任一能力若重新启动，需新的 PRD 范围、安全评审、恢复设计、支持矩阵与独立发布门槛。

## 13. 每个里程碑的完成定义

一个里程碑只有在以下事项全部完成后才算完成：

1. 用户可见结果与 [product/PRD.md](./product/PRD.md) 对应，不用内部实现代替用户结果；
2. 代码、数据库迁移、IPC 契约、文案和规范同步；
3. 正常、禁止、fallback、取消、错误和恢复状态都有测试；
4. 所有新增写能力完成真实支持介质测试；
5. 安全授权由核心层强制，前端显隐不改变结论；
6. 活动记录能解释每个处理和跳过对象；
7. 相关 P0/P1 问题关闭，已知限制在产品内可见；
8. 实际运行入口、截图、交互、构建、测试和无障碍声明都有当前证据；
9. 没有用锁定步骤、未来入口或 dormant schema 冒充已交付功能。
