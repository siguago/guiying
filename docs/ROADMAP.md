## 当前实施快照（2026-08-11）

- 已完成：产品/安全/文件系统/数据模型规范、设计系统与桌面证据界面、无主动变更的内存扫描核心、完整 BLAKE3 后逐字节 D1 定案、根句柄路径保护、版本化报告、可取消单任务桌面运行时、SQLite 安全迁移与自动化门禁。
- 正在进入：Phase 1 的持久化索引、重启续扫、真实外置卷矩阵与基础时间元数据提取。当前取消是合作式停止，不等同于持久化暂停。
- 尚未开放：任何时间写入、隔离、恢复或永久清理。相关 SQL 只是一份受测试的安全契约，不是可执行写能力。
- 本轮复核记录：[engineering/M0_REVIEW.md](./engineering/M0_REVIEW.md)。

## 1. 路线原则

归影采用“先证明只读结果，再获得有限写权限”的交付顺序。阶段完成以可验收的安全能力为准，不以界面完成度或功能数量为准。

1. 先完成 D1 字节级重复，再做 D2/D3；
2. 先发布只读扫描，再开放同卷隔离；
3. keeper 选择和 time donor 迁移从数据模型开始就解耦；
4. 文件系统能力靠运行时探测，不靠名称白名单；
5. 所有写功能由同一个核心安全策略层授权，前端不能绕过；
6. 任一 P0 门槛未通过，产品必须保持或回退到只读模式；
7. 永久清理最后实现，并独立评审。

规范入口：

- 产品范围与验收：[product/PRD.md](./product/PRD.md)
- 安全不变量、事务与故障注入：[engineering/SAFETY.md](./engineering/SAFETY.md)
- 文件系统能力与 fallback：[engineering/FILESYSTEMS.md](./engineering/FILESYSTEMS.md)

## 2. 版本与发布通道

| 通道 | 能力 | 面向对象 |
| --- | --- | --- |
| Internal | 可破坏性测试卷、完整诊断和故障注入 | 开发团队 |
| Preview Read-only | 扫描、D1 报告、时间分析，不写用户卷 | 早期用户 |
| Beta Quarantine | 通过 P0 的文件系统上执行同卷隔离与恢复 | 有独立备份的测试用户 |
| Stable | 支持矩阵内的扫描、时间修复、隔离、恢复 | 普通用户 |

各通道必须在界面中明确显示当前写能力。功能旗标只能关闭能力，不能绕过安全策略打开未通过门槛的能力。

## 3. Phase 0：工程基线与可审计契约

### 目标

建立项目结构、数据模型、设计语言与安全契约，使后续实现不会把“重复文件”“照片资产”“保留项”和“时间来源”混为一谈。

### 交付物

- PRD、安全设计、文件系统策略、路线图、架构与数据模型文档；
- Rust/Tauri 核心与 React/TypeScript 前端骨架；
- 统一错误分类、结构化日志、规则版本和事务 ID；
- SQLite schema：卷、扫描根、文件快照、内容摘要、重复组、逻辑资产、keeper、time donor、时间证据、执行计划与事件；
- 设计系统基础：色彩、排版、间距、状态、风险语义和无障碍要求；
- 测试夹具生成器和临时测试卷方案。

### 退出条件

- 规范文档完成评审并在仓库留档；
- keeper 与 time donor 是独立实体/关系，不能用同一字段表示；
- 核心安全策略可在无 UI 环境测试；
- 默认构建不包含任何永久删除入口；
- CI 运行格式、静态检查、单元测试和基础跨层契约测试。

## 4. Phase 1：只读精确扫描 MVP

### 目标

向真实用户交付不会改变照片的、可暂停和增量的 D1 重复扫描。

### 交付物

- 扫描根选择、重叠目录去重、挂载边界与默认排除；
- 流水线：大小分桶、分段快速指纹、流式 BLAKE3；
- 本机 SQLite 增量索引、暂停/继续、掉盘等待与重新识别；
- D1 重复组、路径/大小/时间对比和 keeper 建议；
- 基础 EXIF/QuickTime/sidecar 时间提取，原始值与置信度留档；
- 只读卷信息与未经写探测的风险提示；
- JSON/CSV 报告，异常与跳过列表；
- 解析器隔离、超时、内存和像素限制。

### 验收与退出条件

- 基准语料 D1 召回率和准确率 100%；
- 文件名、时间或快速指纹碰撞不会产生 D1；
- 旋转硬盘与 SSD 上均无失控并发，单文件内存使用为常数级；
- 重启、暂停、重新插入原卷可安全续扫；同名替换卷不能复用索引；
- 损坏媒体只影响自身解析，不影响哈希主进程；
- 用户可完整理解 keeper 建议和 time donor 建议是两个决策；
- 发布为 Preview Read-only。

## 5. Phase 2：逻辑资产与时间证据完善

### 目标

在仍保持只读的前提下，把时间分析和照片逻辑资产关系做到可用于安全执行。

### 交付物

- Live Photo 配对、AAE、XMP、Takeout JSON、THM、AppleDouble 关系模型；
- RAW+JPEG、ProRAW、HDR、Portrait、连拍和编辑版分类；
- 时间证据图：来源、原始值、偏移、精度、独立性和冲突；
- 复制时间簇检测、异常日期、DST、整数小时偏差和无时区处理；
- keeper 评分解释及用户优先目录；
- time donor 选择、迁移预演和 donor 保留规则；
- data fork 相同但扩展元数据不同的差异报告。

### 验收与退出条件

- 模糊 sidecar 或 Live Photo 关系始终被标记，不能进入自动候选；
- 重复副本数量不会被作为独立时间证据票数；
- 所有时间显示均能追溯原始字段、时区语义与解析器版本；
- 测试语料中的非法日期、复制时间和强证据冲突全部按预期降级；
- 执行预演能列出 keeper、donor、伴随项和潜在元数据损失。

## 6. Phase 3：文件系统探测、事务隔离与恢复

### 目标

仅在能证明安全的卷上开放同卷隔离，并在任意中断点恢复到确定状态。

### 交付物

- 完整卷身份与 mount session 绑定；
- 按 [engineering/FILESYSTEMS.md](./engineering/FILESYSTEMS.md) 实现只读/写能力探测；
- 本机 SQLite + 卷上 append-only 清单；
- 冻结计划、执行前完整哈希和逐字节复核；
- 按文件可重入事务状态机；
- no-replace 同卷隔离、目标读回验证；
- rename 不可信时的复制到 `.partial`、完整验证、保留源 fallback；
- 启动/重新挂载对账、冲突恢复目录、幂等恢复；
- 卷级熔断：I/O、权限、空间、日志或能力异常后停止后续写入；
- 执行前预览、活动记录和完整审计导出。

### 验收与退出条件（P0）

- [engineering/SAFETY.md](./engineering/SAFETY.md) 第 13 节全部通过；
- 在每个状态转换前后强杀进程，不违反 Last-good-copy；
- 哈希、移动、日志和恢复时拔盘，重挂后能对账且不猜测；
- 短读/短写、磁盘满、权限变化和卷变只读均触发卷级停止；
- 同名换盘、TOCTOU、symlink 置换、并发修改均拒绝执行；
- 恢复不覆盖不同内容且可重复执行；
- APFS、HFS+、exFAT 真实外置测试卷通过支持范围内的全套测试；
- 未通过能力探测的 NTFS、网络/FUSE 和未知卷保持只读或复制保源；
- 达标后才进入 Beta Quarantine。

## 7. Phase 4：高置信度时间修复

### 目标

在 keeper 与 donor 解耦的基础上，安全修复受支持卷上的文件创建/修改时间。

### 交付物

- birthtime 与 mtime 独立能力、精度和舍入探测；
- 时间写入子事务：保存旧值、写入、关闭重开、读回、内容哈希复核；
- donor 信息迁移完成前的强制阻断；
- birthtime 不可写、仅 mtime 可写、已知舍入和未知行为的 fallback；
- 时间修复撤销和完整审计；
- APFS/HFS+/exFAT/受控 NTFS 驱动的字段级支持矩阵。

### 验收与退出条件

- birthtime、mtime 任一写后不一致均不会被静默报告为成功；
- time donor 写回失败时从未被隔离；
- 时间写入不改变媒体内容哈希；
- 重新挂载后随机抽样验证符合能力档案；
- DST、无时区、精度降低和冲突状态在 UI 与导出中一致；
- 真实介质故障注入及恢复演练通过后进入 Stable 候选。

## 8. Phase 5：D2 画面相同与 D3 视觉相似

### 目标

帮助用户发现非字节相同的冗余内容，同时保持人工决策边界。

### 交付物

- D2：方向、色彩和像素归一化的解码比较；
- D3：感知哈希/本地向量相似度、连拍和编辑版本候选；
- 原图/导出、HDR/SDR、RAW/JPEG、裁剪/滤镜差异解释；
- 并排对比、缩放、关键元数据与质量指标；
- 模型/阈值版本化和结果可重建；
- 受限解析/推理进程，不联网。

### 验收与退出条件

- D2/D3 永不被 D1 批量规则隐式选中；
- 所有候选均显示判定等级和不能自动处理的原因；
- 解析失败、色彩空间未知、动画/多帧歧义时仅报告；
- 用户操作仍走冻结计划、事务与恢复协议；
- 建立多格式、多设备、多编辑器的回归语料。

## 9. Phase 6：支持面扩展与永久清理评审

### 目标

在已有安全协议上扩展文件系统与高级归档能力；永久清理仍需独立决策。

### 候选交付物

- 经版本认证的第三方 NTFS 驱动支持；
- 指定 SMB/NAS 实现的受控支持；
- 媒体内部 EXIF/QuickTime 修复或 XMP sidecar 高级模式；
- 可选归档规则、目录重组与重命名预演；
- 永久清理的独立事务、保留期、备份声明与重新验证；
- 多语言、完整 VoiceOver 和性能自适应优化。

### 前置门槛

- 每个新驱动/服务器组合拥有独立能力与故障测试记录；
- 媒体内部元数据修改必须产出新版本、重新哈希并可恢复；
- 永久清理通过单独安全评审，且禁止宽泛递归删除；
- 清理前逐项证明 keeper 仍存在、可读且内容匹配；
- 用户明确理解隔离清理后无法由归影恢复，并声明存在独立备份。

## 10. 横向工作流

以下工作贯穿所有阶段：

### 10.1 测试语料

- 合成碰撞/边界文件、真实多设备照片副本和多种 sidecar；
- 记录预期 D1/D2/D3、逻辑资产关系和时间证据；
- 语料中照片需具备使用授权并去除不必要隐私内容；
- 每次修复 bug 都增加最小回归夹具。

### 10.2 故障注入

- 系统调用层注入 EIO、ENOSPC、权限、短读/短写和延迟；
- 每个状态点进程终止；
- 可安全拔出的专用外置测试盘演练；
- 日志截断、数据库损坏、网络断连和同名换盘；
- 结果自动检查 Last-good-copy、No-overwrite、Donor-preservation。

### 10.3 可观测性与隐私

- 结构化事件包含事务 ID、规则版本和错误分类；
- 默认日志不包含媒体内容，路径可脱敏；
- 用户可导出可读报告和机器可读报告；
- 不接入默认上传型遥测，未来任何遥测都需明确 opt-in。

### 10.4 产品与无障碍 QA

- 每个风险状态都有非颜色表达、明确动作和可恢复路径；
- VoiceOver、键盘、缩放和高对比度回归；
- 执行前文案能让用户复述 keeper、donor、隔离与实际空间含义；
- 不使用“100% 安全”“已备份”等超出保证范围的表述。

## 11. 明确延期项

在前置阶段未达标前，不启动以下能力：

- 自动处理 D2/D3；
- 修改 `.photoslibrary`；
- 网络/云端直接清理；
- 跨卷复制后自动删除源文件；
- 以文件名/时间/快速哈希作为隔离证据；
- 自动永久清空隔离区；
- 无可验证恢复路径的媒体内部元数据原地改写；
- 需要 root 权限或修改系统挂载配置的方案。

## 12. 每阶段完成定义

一个阶段只有在以下事项全部完成后才算完成：

1. 代码、数据库迁移、用户文案和规范文档同步；
2. 正常路径、禁止路径、fallback 和恢复路径均有自动化测试；
3. 新增写能力完成支持矩阵内真实介质测试；
4. 重要决定、已知限制和未解决风险在仓库留档；
5. 安全策略由核心层强制，UI 隐藏/显示不影响授权结论；
6. 报告可以解释每个被处理或跳过的对象；
7. 没有未关闭的 P0 数据完整性问题；
8. 发布说明准确列出支持的文件系统、字段和 fallback。
