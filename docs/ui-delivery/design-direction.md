# 归影 vNext UI 设计方向

| 项目 | 内容 |
| --- | --- |
| 方向状态 | Implemented baseline；已用于本轮结果决策、预览、隔离与恢复界面 |
| 交付形态 | existing repository / desktop / zh-CN |
| 产品范围 | D1 确定重复的选择、预览、可恢复隔离与恢复 |
| 方向名称 | 中性本地照片工作台 |
| 签名装置 | Keep / Move 双轨 |
| 当前证据 | 本轮已在同一生产入口完成浏览器状态证据；原生真实卷证据仍按门禁补齐 |

### 当前实现事实（交付前必须复核）

- 本轮生产界面已加入基于合成数据的“选择 keeper → 预览 → 演示隔离 → 演示恢复”交互闭环；它用于验证信息架构、Keep/Move 双轨和状态文案，不访问或移动本地文件。
- 原生单组 D1 隔离/恢复原型与前端命令适配在同一工作树中，但已受双重 release gate 保护：Cargo feature 和前端环境开关均默认关闭。标准构建不会弹出隔离目录选择器，也不会移动或恢复真实文件。内部原型只能用于专用可破坏测试卷；双份追加日志、启动对账、C3 能力探测、逻辑资产门、Tauri E2E 和真实外置卷故障矩阵全部通过前不得开放。
- 本节是并行实施期间的事实快照。最终交付者必须按最终代码和测试结果更新它；不得把合成闭环、源代码存在、Rust 单元测试或 dormant command 分别冒充可用的原生闭环。

## 1. 用户结果与视觉任务

用户来到归影不是为了审核一份取证报告，而是为了回答三个问题：

1. 这几份是否真的完全相同？
2. 我要把哪一份留在原位？
3. 哪些会移入隔离区，之后怎样找回来？

界面必须让用户在不理解 BLAKE3、封印、descriptor、mount session 或内部 Phase 的情况下完成这三个判断。技术证据仍然存在，但只在“为什么这样判断？”中按需展开。

North star：**像在本机工作台上整理一组明确的文件，而不是在档案台账里复核一份技术结论。**

## 2. 视觉来源分类

| 来源 | 分类 | 处理 |
| --- | --- | --- |
| 用户反馈：流程繁琐、结果页无法继续、不理解步骤用途 | approved product evidence | 直接决定流程简化、可完成性和文案层级 |
| D1 只处理字节完全相同、默认本地、异常即保留 | approved product truth | 保留为信任基础，但改写为用户语言 |
| macOS 原生目录选择、可调整窗口、键盘/VoiceOver | approved platform constraint | 采用桌面工作台密度、系统字体与常见输入行为 |
| 当前截图与“档案纸上的校验台账” | rejected anti-reference | 不再继承其材质、配色、构图、阶段导航和术语密度 |
| 现有品牌标记与 Lucide 功能图标 | provisional | 品牌标记可暂留；功能图标仅作语义辅助，需按新几何复核 |
| 现有 React/Tauri/Rust 架构与 DTCG token 管线 | approved implementation source | 原位演进，不创建平行预览站 |
| 其他仓库的 token、字体、提示词、图像与组件 | unrelated | 不复用；本方向没有跨项目视觉值来源 |

用户对现有产品体验的否定重置此前视觉连续性。“已经实现”不是继续保留旧视觉语法的理由。

## 3. 明确的 anti-reference

以下组合是回归检查基线，不是可轻微调色后继续使用的风格：

- 暖纸白或米色大面积底色；
- 森林/墨绿作为品牌主色，配琥珀、暗金、砖红或鼠尾草；
- 档案、台账、证据脊柱、封印、手稿、纸张或账本隐喻；
- 固定四步工程流程、未来步骤加锁和 “Phase 1 · Persistent evidence” 等内部标签；
- 大标题 + 工程状态条 + KPI 数字格 + 证据列表组成的审计报告版式；
- 常态界面里大量等宽体、哈希、英文内部状态与微小灰字；
- 把报告导出放在结果页主操作区；
- 用暖纸/墨绿/宋明体等“中文产品”惯性风格包装简体中文内容。

拒绝原因不是这些元素永远不能使用，而是它们在归影中没有品牌、材料或文化依据，且已经使产品任务显得复杂、不可继续。中文是本地化约束，不是传统、档案或“东方编辑感”的设计依据。

## 4. 内部方向比较

方向开放时内部比较了三个在构图、字体、材质和交互上实质不同的方案：

| 方向 | 构图 | 字体与色彩/材质 | 交互性格 | 结论 |
| --- | --- | --- | --- | --- |
| A. 中性本地照片工作台 | 目的地导航 + 分组主从工作区 + 底部决策摘要 | macOS 系统无衬线；冷中性画布、白色工作面、蓝/紫双轨 | 明确、平静、可撤回；选择 keeper 后即时重排 Keep/Move | **选择**。最直接支持用户任务，且不依赖照片预览或技术知识 |
| B. 照片联系表 | 以缩略图网格和全屏对比为主 | 深灰照片画布；较软的人文无衬线；以图像色彩为视觉主体 | 浏览和放大优先，手势式挑选 | 不选。D1 文件可能视觉不可预览，海量组扩展差，也容易让用户误以为在判断画面相似 |
| C. Finder 式操作队列 | 高密表格、列排序、右侧检查器和命令栏 | 纯灰系统材质；紧凑系统字体与大量等宽数字 | 键盘优先、专家高密度、批处理强 | 不选。效率高但把身份、路径、状态机暴露为日常认知负担，重复当前“过于技术化”的问题 |

选择 A 不是三个方案的调色折中。它以 Keep/Move 决策关系而不是证据链或缩略图作为结构来源。

## 5. 方向契约与来源

| 身份维度 | 方向 | 来源与理由 | 约束 |
| --- | --- | --- | --- |
| 构图 | 桌面主从工作区；一屏一个决定；底部显示当前计划 | 用户要在同一组内比较路径并选择 keeper | 不使用锁定步骤轨道、卡片墙或 KPI 仪表盘 |
| 字体 | `-apple-system` / `BlinkMacSystemFont` / `SF Pro Text` / `PingFang SC` / sans-serif；数字使用 tabular 特性 | macOS 本地工具、中文覆盖和高密信息可读性 | 普通标签不使用等宽体；不因中文采用宋/Ming/FangSong |
| 画布与表面 | 冷中性浅灰画布、纯白工作面、细分隔线；只给弹窗/浮层真实 elevation | 照片和路径不应被带色材质污染；层级来自工作关系 | 无纸纹、玻璃、渐变、发光、装饰阴影和嵌套卡片 |
| 色彩 | 墨色文字；钴蓝用于主动作和 Keep；清晰紫用于 Move/隔离目的地；绿只表示完成，红只表示阻断，黄只表示警告 | Keep/Move 是两种工作去向；隔离可恢复，不应伪装成删除危险 | 状态均配合文字、图标或线型；不得让绿/琥珀重新成为品牌套装 |
| 几何 | 4/6/10 px 小半径族、1 px 分隔、44 px 最小高频操作目标 | 桌面精度与可访问操作尺寸 | capsule 只用于状态/筛选；按钮、行、面板不全部胶囊化 |
| 图标 | 单一线性家族，18/20 px 常用光学尺寸；保留、移动、恢复使用不同方向性图形 | 图标帮助识别动作，但不替代动词 | 不给每个功能套彩色圆角方块，不混用图标家族 |
| 动效 | 选择 keeper 时双轨位置 140–180 ms 连续过渡；执行状态按真实事件更新 | 只承担连续性和反馈 | 不阻塞下一步；减少动态时取消位移动画并即时换位 |
| 签名 | Keep / Move 双轨横贯成员、预览和活动结果 | 来自重复整理的核心决策，而非通用装饰 | 两轨总有文字与图标；Move 明写“移入隔离区”，不能仅靠紫色 |

### 5.1 建议的语义色基线

以下值是实现起点，必须经实际渲染与对比度检查后才能锁定：

| 角色 | 起点 | 用途 |
| --- | --- | --- |
| `surface.canvas` | `#F4F6F8` | 应用画布 |
| `surface.work` | `#FFFFFF` | 主工作面 |
| `text.primary` | `#17202A` | 主要文本 |
| `text.secondary` | `#5C6875` | 辅助文本 |
| `border.subtle` | `#D9DEE5` | 分隔和控件边界 |
| `action.primary` / `track.keep` | `#245FD1` | 主动作、保留轨 |
| `track.move` | `#6B57C7` | 移入隔离区轨 |
| `status.success` | `#18794E` | 已验证完成；不是品牌底色 |
| `status.warning` | `#9A5B13` | 为安全保留或需复核 |
| `status.danger` | `#C13C3C` | 阻断、不可继续、不同内容冲突 |
| `focus.ring` | `#0B6BDF` | 可见键盘焦点 |

不从旧 token 机械映射这些值。实现时应在既有 DTCG 源中重建语义角色，并记录迁移；旧暖纸、墨绿和琥珀品牌角色不能改名后继续出现。

## 6. Retain / Refine / Replace / Add

### Retain

- React/Tauri/Rust 的真实产品入口和现有安全架构；
- 原生目录选择、同进程暂停/继续/停止和路径授权边界；
- D1 完整内容证明、异常即保留和本地隐私事实；
- 已证明可用的键盘焦点恢复、分页失败保留上一成功页和 reduced-motion 基础；
- Lucide 作为功能图标候选源，前提是统一光学规格。

### Refine

- 扫描进度：从算法阶段台账改为用户进度，技术层按需展开；
- 重复组列表：从证据行改为以 keeper 决策为中心的成员工作区；
- 时间和原始元数据：从右侧主详情改为高级解释与阻断原因；
- 历史：从“封存报告”改为“活动”，先讲发生了什么，再提供技术导出；
- 风险文案：从抽象“当前锁定/封印”改为对象、后果和恢复动作。

### Replace

- 暖纸、墨绿、琥珀和档案台账视觉语法；
- 固定四步流程轨道、未来能力加锁和 Phase 标签；
- 证据脊柱作为全局签名；
- 主界面中的 KPI 数字格与大面积技术摘要；
- 结果页占主位的 JSON/CSV 导出表单；
- 以小号灰字和等宽体制造“专业感”的层级。

### Add

- Keep / Move 双轨成员决策；
- “可整理 / 为安全保留”资格分区；
- 系统建议理由与整组暂不处理；
- 粘性 Keep/Move/Skip 决策摘要；
- 执行预览、真实状态进度、完成结果；
- 隔离区与单项/组/活动恢复；
- 不同内容冲突的安全恢复路径；
- 活动中的计划—实际—恢复链路。

## 7. 信息架构与页面

### 7.1 主导航

- **整理**：当前目录、扫描、决策、预览、执行和完成；
- **隔离区**：被移动文件和恢复；
- **活动**：历史扫描、执行、跳过、对账、恢复与报告导出；
- **设置**：优先保留目录、排除、性能与隐私。

只有真实可用的目的地进入发布构建导航。Closed Beta 之前不显示空的“隔离区”占位，也不显示时间修复、相似照片和永久清理。

### 7.2 必需页面与状态

| 页面 | 主问题 | 主操作 | 必需状态 |
| --- | --- | --- | --- |
| 整理起点 | 要检查哪个位置？ | 选择照片文件夹 | 未选择、权限过期、卷不在 |
| 扫描 | 正在做什么，还要多久？ | 暂停/继续、停止 | 枚举、比较、暂停、取消中、失败 |
| 重复决策 | 每组留哪份？ | 保留这一份、暂不处理 | 可整理、为安全保留、选择变化、长路径 |
| 执行预览 | 会留什么、移什么、跳过什么？ | 将 N 个副本移入隔离区 | 计划有效、计划过期、卷只读、能力不足 |
| 执行 | 真实发生了什么？ | 停止尚未开始项 | 准备、移动、验证、跳过、需对账 |
| 完成 | 下一步是什么？ | 查看隔离区、恢复本次移动 | 全部完成、部分完成、需要处理 |
| 隔离区 | 哪些可以找回？ | 恢复 | 卷不在、原路径冲突、已恢复、需对账 |
| 活动 | 过去做了什么？ | 查看详情；次要菜单导出 | 空、分页、导出、读取失败 |

## 8. Keep / Move 双轨

双轨是结构规则，不是两枚彩色标签。

### 8.1 组内行为

- 每个成员行显示缩略识别符、文件名、可区分路径、格式、大小和必要风险；
- “保留这一份”使用同组单选语义；选中后该成员进入 Keep 轨；
- 其他合格成员自动进入 Move 轨，并持续显示完整文案“移入隔离区”；
- 选择新 keeper 时，旧 keeper 与新 keeper 在两轨间交换，底部计划摘要同步更新；
- 用户若不愿只留一份，应选择“整组暂不处理”，而不是制造多个未定义角色；
- 被阻断组没有 Move 控件，只显示“为安全保留”与原因/解决办法；
- 不支持拖拽作为唯一交互；指针、键盘和 VoiceOver 走同一语义状态。

### 8.2 跨页面连续性

- 决策页：双轨表达当前意图；
- 预览页：两列清单表达 Keep 原路径与 Move 隔离目标；
- 执行页：Move 轨变为准备/移动/已验证事件，Keep 轨持续显示“仍在原位”；
- 活动页：最终结果仍沿用 Keep/Move 标签，并单列 Skip；
- 恢复页：从 Move/隔离轨指向原路径或安全冲突路径，不能用“撤销成功”掩盖实际去向。

## 9. 内容语言

### 普通界面示例

| 不使用 | 使用 |
| --- | --- |
| 只读报告已完成 | 已找出 709 组完全相同的文件 |
| 逻辑重复上限 592 MiB | 这些副本共 592 MiB；移入隔离区暂不会释放空间 |
| D1 · 逐字节确认 | 内容已完整比对 |
| 时间：按需审阅 | 拍摄时间有差异，已为安全保留 |
| 执行前再次复核 | 移动前会再次检查文件是否变化 |
| 当前锁定 | 此版本不会移动照片 |
| 导出封存报告 | 导出活动记录 |

技术术语可以出现在高级证据、诊断导出和开发构建中，但必须有普通语言摘要，且不能成为完成主任务的前置知识。

## 10. 组件、布局与适配

### 10.1 桌面布局

- 典型宽度：左侧 216–232 px 目的地导航，右侧为一块连续工作面；
- 决策页在宽屏采用组列表 + 成员工作区；解释面板按需覆盖或成为支持栏，不固定占用三栏；
- 1024 px 宽度保留组上下文、Keep/Move 和粘性摘要；解释详情使用 sheet/drawer，不把所有面板堆叠成卡片；
- 主操作与当前计划摘要保持可达，但不能遮住列表末项；
- 路径允许两行和中部省略，完整值可通过语义描述与显式详情获取。

### 10.2 组件约束

- 列表行、分组和侧栏优先用间距、对齐、分隔线和背景字段，不给每层套卡片；
- 按钮分 primary、secondary、quiet 与 danger；Move/隔离是可恢复操作，不使用 danger 皮肤；
- 状态胶囊仅用于短状态，不承载长解释；
- 对话框仅用于最终确认、冲突或跨上下文恢复，不把每次 keeper 选择做成弹窗；
- 缩略图不是 D1 判断依据；加载失败时保留文件图标、文件名和路径，不影响选择。

## 11. 可访问性

- keeper 使用同组 radio 语义；Move 状态作为相关描述宣布；
- 轨道切换后通过 aria-live 简短报告“保留项已改为 X，另外 N 个副本将移入隔离区”；
- 颜色之外持续显示 Keep/Move/Skip 文本、图标与位置；
- 所有高频目标最小 44 × 44 CSS px 或具有等效连续行点击区；
- 可见焦点在中性与轨道色背景上均通过对比度门槛；
- 执行与恢复进度使用确定/不确定进度语义，并允许屏幕阅读器获取当前对象；
- 200% 文本下不裁切主操作；长中文、英文路径和混排状态经过内容压力测试；
- reduced-motion 下轨道切换即时完成，状态不依赖动画；
- VoiceOver 真机验证是 Closed Beta 门槛，自动 axe 不能替代。

## 12. Anti-template 方向门

| 触发项 | 决策 | 理由/改法 |
| --- | --- | --- |
| 暖纸/墨绿/琥珀/档案组合 | rework | 已是用户否定体验的 anti-reference，全部重建 |
| 固定侧栏 | allow with constraint | 桌面目的地稳定且需跨任务返回；内容必须是可到达地点，不是开发步骤 |
| KPI 卡片墙 | rework | 数字只服务当前决策，进入一行计划摘要或正文 |
| 卡片嵌卡片 | rework | 用工作面、分隔线、表头和行状态表达结构 |
| 系统无衬线字体 | allow with constraint | 来自 macOS 平台、CJK 覆盖和高密阅读；通过角色、字重、度量与布局建立身份 |
| 统一圆角和胶囊 | rework | 采用小半径族，胶囊只给短状态/筛选 |
| 彩色圆角图标块 | rework | 图标只辅助具体动作，不作装饰模块 |
| 常驻三栏检查器 | rework | 证据按需打开，核心决策保留比较宽度 |
| 通用仪表盘壳 | rework | 归影结构由组内 Keep/Move 与恢复链路决定 |
| 中文驱动传统/档案风格 | rework | locale-style separation 不通过；中文只决定排版和测试 |

### 方向门结果
