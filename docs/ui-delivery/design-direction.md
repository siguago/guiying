# 归影 Phase 1 UI 设计方向

## 范围与用户结果

本交付覆盖当前 Phase 1：用户通过原生选择器授权一个照片目录，理解扫描不提供主动变更操作，看到扫描进度，在目录枚举安全点暂停并于同一应用进程内继续，并复核经过完整哈希筛选与逐字节确认的重复组、封印拍摄时间证据和历史只读报告。历史结果可另存为 JSON/CSV 摘要或完整重复证据；跨进程续扫、隔离、永久删除、元数据写回和批量执行均未开放。

用户离开这一里程碑时应当明确三件事：哪些文件内容完全相同、逻辑重复大小上限是多少、哪些时间只是文件系统弱证据而不是拍摄时间。

## 视觉命题

方向名称：**档案纸上的校验台账**。

North star：让每个整理结论都像一份可检查的档案记录，而不是一个要求用户盲信的“智能清理”按钮。

界面以偏暖纸白承载内容、墨黑建立层级、证据绿表示已验证事实、琥珀色表示需要人工确认、红色只保留给阻断与危险。整体平静、克制、密度适合桌面工具；不借用照片瀑布流或消费型清理应用的夸张空间数字。

## 签名装置

**证据脊柱**是产品的签名装置。它纵向连接“大小一致 → 抽样指纹一致 → 完整 BLAKE3 一致 → 扫描时逐字节确认”；未来若开放动作，执行前还必须再次复核。组详情并列呈现拍摄时间候选的来源、资格、置信度和冲突，证据链比结论按钮更先出现。

## 设计原则

1. 先边界，后动作：首屏和顶栏持续说明“不主动修改内容、名称、birthtime 或 mtime；读取可能更新 atime”。
2. 结论可追溯：重复与时间结论分别说明来源，不合并为一个神秘评分；当前没有 keeper 或 donor 决策。
3. 风险有词义：绿色只表达已经验证；琥珀表达需确认；锁定态保留可读性，不用低透明度掩盖信息。
4. 未知即保留：错误与缺失状态说明“跳过并保留”，不使用暗示已经安全清理的措辞。
5. 键盘可达：主要流程按自然 DOM 顺序到达，焦点环高对比，目录对话框返回后恢复焦点。

## 布局语法

- 左侧固定工作流轨道：品牌、四步流程、当前扫描范围、本地隐私说明。
- 顶部状态条：运行环境、权限模式与里程碑编号。
- 中央工作区：空态采用编辑式标题和安全凭证；结果态采用重复组主列表与证据详情双栏。
- 1024 px 紧凑桌面下保留完整信息层级，详情区域变为可滚动；不删除安全提示或证据来源。

## 组件与状态

- 主按钮：选择目录、开始只读扫描、查看历史报告；枚举阶段提供暂停/继续与始终可用的停止；危险按钮在 Phase 1 不存在。
- 安全凭证：原生一次性 root token、逐字节内容校验、异常即保留；历史 display path 只作封存显示，不恢复目录权限。
- 进度台账：枚举、抽样、完整哈希、逐字节确认、报告生成；暂停只发生在枚举安全点，退出后不可继续原扫描。
- 重复组行：格式、份数、大小、可回收空间、当前选中态。
- 时间证据：双重提取、来源、值、资格门、置信标签和解释；文件系统时间明确标为独立弱证据。
- 历史目录：显示 complete/partial 覆盖和 complete/partial/not_run/unavailable/failed 五种时间状态；打开后只以限时 result token 分页读取封印证据。
- 历史导出：由系统选择新文件名，界面只接收文件名和一次性授权；提供 JSON/CSV、摘要/完整重复证据与默认隐去/可选显示路径。完整重复证据不含拍摄时间候选/成员/元数据记录、原始字段或定位器；摘要可保留封存报告既有的时间阶段汇总。
- 错误态：给出可恢复动作，不改变源目录。

## 反目标

- 不使用渐变、玻璃拟态、霓虹、装饰性大图或通用 KPI 卡片墙。
- 不用文件名、创建时间或感知相似度直接定案为可删除重复。
- 不把“时间正确的副本”自动等同于“应该保留的最高质量副本”。
- 不在 Phase 1 展示已经可用的隔离、改时或删除控制。
- 不把同一进程内的暂停/继续描述为应用重启后的续扫，也不把报告文件导出描述为照片写入授权。

## 继承约束

生产源位于仓库 `src/`、`src-tauri/` 与 `crates/guiying-{core,metadata,runtime,store,time,volume}/`；DTCG 令牌源位于 `design-system/tokens.tokens.json`，生成 CSS 位于 `src/styles/tokens.css`。功能图标来自 Lucide，品牌标记、应用图标与证据脊柱为仓库原创。所有测试内容使用合成路径与文件名。
